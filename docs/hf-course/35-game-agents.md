# 游戏里的 Agent：会聊天的 NPC 与会行动的 NPC

让 NPC 接一个大语言模型，玩家问话时它可以说得更自然；但它仍可能只是被动的对话接口。一个真正参与游戏的 Agent 需要读取世界状态、决定目标、选择合法行动，并在环境变化后调整策略。差别不在台词是不是“像人”，而在它是否形成了可观察的状态—决策—动作循环。

## 从台词到行动

想象一个 RPG 守卫。对话型 NPC 可以解释城门规则；Agent 型 NPC 则可能发现城门被打开、呼叫同伴、去调查或改变巡逻路线。它需要自主性（何时行动）、适应性（对玩家和环境变化反应）与适度的持久性（记住最近事件）。这不意味着让模型随意改写游戏状态：所有动作仍须经过游戏引擎的权限、合法性和规则校验。

回合制对战尤其适合教学。每回合游戏先给出当前状态和可选动作，Agent 在有限集合内做决定，环境执行并返回新状态。你可以清楚地记录：它看到了什么、选择了什么、动作是否合法、最终胜负如何。

## 为什么实时游戏难得多

快节奏游戏可能以几十帧每秒刷新。LLM 的一次推理、工具调用与网络往返远慢于一帧预算，因此不能让它逐帧决定移动方向。可以把模型放在低频的策略层（如决定目标或战术），让高频控制由传统游戏 AI、规则或专门模型执行；还可以缓存计划、异步更新，但必须处理过期状态。回合制的 Pokémon 对战给模型更长思考时间，因此比较适合作为首个 Agent 实验。

## 看游戏 AI 演示时问什么

已有产品和技术演示展示了自然语言 NPC、记忆与环境感知，例如 2024 年 GDC 的 Covert Protocol、NEO NPCs、使用 NVIDIA ACE 的机甲游戏演示，以及以说服 NPC 开门为玩法的 *Suck Up!*。它们证明对话体验可以改变，但并不自动证明 NPC 具有自主规划：需要看它能否自行触发行动、调用什么世界 API、状态是否延续、错误是否可恢复。

相关产品状态会随时间变化，不要把某次演示中的“即将发布”当成今天的事实。学习时更重要的是抽取架构问题：自然语言如何映射到有限的游戏动作？模型能看到哪些状态？行动时延怎样影响体验？策略记忆由谁维护？如何防止模型生成游戏规则以外的动作？

## 一个设计练习

给 NPC 设定“保护城门”的目标，列出它能观察的三个状态（门是否打开、附近是否有玩家、同伴位置）和三个动作（巡逻、呼叫同伴、关门）。再设计一个无效动作的回退规则。如果模型提议“传送到地图外”，游戏引擎必须拒绝，Agent 应在下一轮看到失败结果并重新决策。

## 面试会怎么问

**问：LLM 驱动的 NPC 为什么不一定是 Agent？** 答：会生成自然语言不等于会自主读状态、设目标、选动作并观察后果。判断重点是可执行的闭环，而非对话拟人程度。

**问：为什么不能让大模型控制每一帧？** 答：推理和网络延迟通常超过帧预算。可把 LLM 放在低频策略层，用确定性或专用系统执行高频动作，并处理策略过期和非法动作。
