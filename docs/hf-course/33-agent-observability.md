# Agent 可观测性：看见每一步，才知道哪里出了错

用户只看到最后一句回答；工程师却要知道 Agent 为什么这样答：它调用了哪个模型、查了什么、工具返回了什么、耗时和费用落在哪里、是否遇到提示注入或失败重试。可观测性就是通过日志、指标和追踪理解这些内部行为；评估则利用这些数据和测试集，判断行为是否达到目标。

## Trace、Span 和业务结果

一次用户请求通常是一条 trace（追踪）；其中的模型调用、检索、工具执行、解析与后处理是多个 span（跨度）。一个请求如果先搜索两次、再调用模型三次，你需要看到它们的父子关系和耗时，才能发现“回答慢”究竟来自搜索还是模型。日志保留事件细节；指标便于跨请求看趋势；trace 帮你重建单次事件的因果链。

以“回答某个多跳问题”为例，成功率只告诉你答对了几题，trace 会告诉你：第一步检索是否找错网页、第二步是否重复搜同一问题、第三步是否用工具结果回答。业务结果和运行过程都要记录，但不应把完整用户隐私、Secret 或敏感文件无条件上传到观测平台；必要时做脱敏、抽样、访问控制和保留期限管理。

## 该监控哪些指标

| 类别 | 具体看什么 | 指标异常时先排查 |
| --- | --- | --- |
| 延迟 | 整体响应时间、各模型/工具 span 耗时、尾延迟 | 是否多了一次模型循环、慢 API、串行调用 |
| 成本 | token、模型费用、外部 API 费用、单任务平均/分位成本 | 无效重试、长上下文、循环调用 |
| 可靠性 | 工具超时、HTTP 错误、解析失败、任务失败率 | 权限、额度、schema、外部服务 |
| 质量 | 正确性、任务完成率、引用有效性、用户反馈 | 检索与证据、规划、格式、模型漂移 |
| 安全 | 注入检测、越权工具调用、有害输出 | 数据来源、工具权限、审核策略 |

用户点赞/点踩是显式反馈；立刻重问、改写问题、点击重试是隐式信号。两者都不等同于准确率：用户可能满意一个流畅但错误的回答，也可能给正确但不符合期待的回答差评。必须先为具体任务定义“成功”，再挑指标；数学题可与标准答案比，客服任务可能看问题是否真正解决，RAG 还要检查证据是否支持结论。

LLM-as-a-Judge 能按规则为输出打分，但它自身也会偏差、受提示影响并产生费用。用人工标注样本校准，检查评判者在边界案例和不同群体上的一致性，不能把一个自动分数当成最终真值。

## 离线评估与在线评估怎么配合

离线评估在受控题集上运行，可重复、可在改代码时快速回归。题集应有标准答案或可检验的行为准则，既包含小型冒烟测试，也包含覆盖正常、边缘和失败场景的大集。注意数据污染、样本泄漏、标准答案过期；固定题集能比较版本，却不保证覆盖真实用户的新问法。

在线评估观察真实流量，能发现题集没想到的使用模式、环境漂移与服务故障。可以收集反馈、做影子测试或 A/B 实验，但要保护隐私、避免影响真实用户，并承认线上样本不一定有可靠标签。

有效循环是：离线基线 → 受控发布 → 在线监测 → 把经过脱敏和人工审核的失败样本加入离线集 → 修正方案 → 再回归。只做离线容易“刷题”；只看线上又难以定位到底是哪次改动造成回退。

## OpenTelemetry 在其中的位置

OpenTelemetry 提供遥测数据的通用概念和传输方式；smolagents 等框架可通过相应 instrumentation 产生 span，再由 OTLP exporter 发送到 Langfuse 或其他兼容服务。Langfuse/Arize 等平台在其上提供仪表板、数据集或评估功能。选择平台时看框架集成、数据驻留、权限、成本和可迁移性，而不是只看截图。下一篇会把 smolagents + OpenTelemetry + Langfuse 跑通。

## 五题自测

先自己回答，再核对后面的解析。这组题是概念检查，不计分。

1. **可观测性主要指什么？** 是通过日志、指标与 trace/span 理解 Agent 内部行为，而非只看界面、代码风格或成本。
2. **延迟、单次成本、用户反馈、代码行数，哪一个不是典型运行指标？** 代码行数。前三项反映运行表现，代码行数不能说明一次请求是否成功。
3. **离线评估的核心是什么？** 在受控数据集上对照已知答案或预期行为。单纯看实时日志不等于完成评估。
4. **在线评估最大的补充价值是什么？** 捕捉真实用户交互、意外查询和环境变化；它不会消除离线测试的必要。
5. **OpenTelemetry 的角色是什么？** 标准化采集和导出遥测的埋点接口，不是自动修 bug 的工具、专用日志数据库或模型参数优化器。

## 面试会怎么问

**问：Agent 的 trace 和普通接口日志有何区别？** 答：trace 连接同一次请求的模型、检索、工具和后处理步骤，可追踪父子关系、耗时与错误，帮助归因；日志多是单点事件。还要把业务答案与调用链关联起来。

**问：为什么在线满意度不能代替离线正确率？** 答：反馈稀疏、有偏，而且满意不代表事实正确。离线集提供可复现对照，在线监测提供真实分布与漂移信号，二者互补。
