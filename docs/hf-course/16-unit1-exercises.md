# Unit 1 自测：用 11 道题检验 Agent 基础

概念课读懂后，先不看下方解析，自己回答这 11 道题。它们承接 Hugging Face Unit 1 的两组不计分练习：第一组检查 Agent、规划、行动与工具，第二组检查 LLM、消息和特殊 token。示例另有在线计分测验；本站把能在正文里完成的题和解析保留下来。

## 先做题

1. 用户问「今天纽约天气怎样？」普通文本模型与可查天气的 Agent，能力差在哪里？
2. 规划在 Agent 中承担什么作用？「记住历史」是否等于规划？
3. 工具能给语言模型增加哪些能力？请举一个信息类、一个操作类例子。
4. 「行动」与「工具」有什么区别？一个行动是否可能用到多个工具？
5. LLM 在 Agent 里通常负责什么？它能否自行保证邮件已经发出？
6. 静态 FAQ 页、普通计算器、能设置提醒的语音助理，哪一个最符合课程中的 Agent 定义？为什么？
7. 工具的代码实现和提供给模型的工具描述分别有什么作用？
8. 模型生成一段工具调用文本后，谁应解析和执行？
9. LLM 通过什么方式学习文本模式？它与固定答案表或规则匹配程序有什么不同？
10. 特殊 token 除了普通文字内容，还承担哪些结构功能？
11. Python 中的 `messages=[{"role": ..., "content": ...}]` 送进聊天模型前，为什么常需经过聊天模板？

## 对照解析

**1.** 普通文本模型可以描述天气或猜测，但不能凭自身预训练知识知道实时状态。接了天气工具的 Agent 可以提出查询，由程序执行并把真实返回交回。若工具失败，它应承认未取得当前天气。

**2.** 规划是确定接下来要做什么、先后或依赖关系以及合适的工具。历史消息或状态存储能为规划提供依据，但存储本身不是规划。复杂任务还要在新观察出现后调整尚未执行的步骤。

**3.** 工具可以获取最新或私有信息，例如网络搜索、订单查询；也可以执行动作，例如生成图像、设置提醒或发消息。工具范围决定 Agent 的实际能力和风险。

**4.** 行动是 Agent 当前要完成的操作，工具是程序可调用的具体能力。例如「解释一张账单为何上涨」可能先用账单查询，再用订阅变更查询；这是一个任务中的多个工具调用。这里的选项也强调两者不能简单互换。

**5.** LLM 读取输入、理解请求、生成下一步决策或答案。发送邮件是否完成，只能由执行器和邮件服务的返回确认。模型的一句话不是外部动作的成功凭据。

**6.** 能理解请求并在授权下设置提醒的语音助理最符合例子。静态 FAQ 只展示固定内容；普通计算器按固定规则计算。若语音助理只播报固定答案、不执行操作，它也不自动成为多步 Agent。

**7.** 工具实现负责真正做事；名称、描述、参数和输出说明让模型知道何时以及如何提出调用。两边不一致时，模型即使选对名称也可能传错参数，或以为工具返回了它实际上没有提供的信息。

**8.** 宿主程序或 Agent 框架应解析、校验、执行，并把真实结果回填。模型可以生成看似完整的 `Observation`，但那仍是生成文本，不是 API 返回。

**9.** 大语言模型通过大量数据上的训练学习序列规律，并在使用时按上下文生成 token。固定答案表按键取预存文本；规则程序按显式条件执行。三者都能作为应用的一部分，但工作机制不同。

**10.** 特殊 token 可标记消息起止、角色边界、助手轮次结束或序列结束。具体 token 因模型而异，不应把不同模型的标记混用。

**11.** 聊天模板把角色消息按目标模型训练时的格式串成输入序列，加入边界标记和必要的生成前缀。模型更换后若仍用旧模板，角色和工具结果可能被误读。

## 面试会怎么问

**问题：请从零解释 Agent 的一次工具调用。** 可以用第 1、7、8、11 题串成回答：用户提出目标；模型在消息和工具描述中选出工具与参数；运行时校验权限与参数，执行工具；真实返回作为观察进入下一轮；模型生成答案，程序检查完成条件。若被追问「模型已经写了 `Observation`」，明确指出那只是生成文本，必须核对外部工具事件。
