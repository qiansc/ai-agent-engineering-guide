# 用 GAIA 检验 Agent：不要只看它会不会聊天

一个 Agent 在演示中回答得很像样，不代表它能完成真实任务。GAIA 把多步检索、网页浏览、工具使用、多模态理解与精确答案放在同一道题里，适合检验“从问题到结果”的整条链路。它不是一张通用智力证书，而是一套有特定数据、题型和评分方法的评估基准。

## GAIA 究竟在测什么

题目通常能用简短、明确的答案作结，但得到这个答案需要组合多项能力：识别问题中的实体，决定先查什么，再处理网页或文件，在不同来源之间交叉核对，最后严格按格式作答。只有推理链看起来漂亮、却没有取得证据，仍可能答错。

题库分三个难度等级：一级通常需要较少步骤与工具；二级需要更复杂的多工具协调；三级需要更长的规划与跨模态处理。“少于五步”“五到十步”是帮助理解难度的粗略描述，不是测评时对每个 Agent 的强制步数限制。

看一道困难题的结构：先在一幅画里按顺时针识别水果，再找到后来用于某部电影的远洋班轮，检索那艘船某个月的早餐菜单，求两个集合的交集，最后按画中顺序输出水果复数名称。它至少包含五类子任务：图像识别、实体消歧、历史资料检索、集合运算和输出格式控制。某一步出错，最后一句答案即使流畅也无济于事。

## 拆题时怎样安排工作

先写清最终答案格式：这里是“按顺时针顺序、逗号分隔、复数形式”。再把未知项列成待验证问题，而不是立刻让模型自由发挥：画中有哪些水果？是哪艘船？菜单里有哪些水果？每条答案来自何处？

接着为每个未知项选工具。图像要用视觉识别或人工核对；船名和菜单要用可追溯的搜索/资料阅读；交集与排序可以在代码里确定性计算。每次工具结果都保留来源和原文片段，尤其注意图片位置、日期、船名同名和菜单 OCR 错误。得到候选答案后，按题目约束做一次独立检查：是否遗漏水果、顺序是否正确、是否使用了复数、是否输出了额外解释。

这是一种可迁移的 Agent 设计方法：把开放任务变成可验证的子问题，再让模型负责规划与解释、让工具负责获取证据、让代码负责确定性变换。

## 分数怎么读才不误导

任何排行榜数字都要连同数据划分、题目数量、评测日期、是否使用外部工具、是否人工介入以及答案规范一起看。不同系统在不同划分上的分数不能直接横比。单次分数尤其容易受搜索索引变化、服务失败、模型抽样和答案格式影响。

课程中的历史示例介绍了 466 道题、验证集与测试集，以及当时若干系统/人类的成绩；这些数值是特定版本和时期的背景材料，不应当作 2026 年的实时排行榜。做自己的实验，最有价值的是建立逐题错误分类：

- **检索失败**：没找到关键网页或附件，或关键词偏题。
- **理解失败**：读到了正确证据，却误解实体、时间、图像位置。
- **规划失败**：漏掉必要子步骤，或顺序错误。
- **执行失败**：工具报错、文件打不开、状态丢失。
- **格式失败**：事实正确，但没有按精确答案格式提交。

错误分类能指导下一次改进；只报一个总分，无法知道该修搜索、视觉、提示词还是工具可靠性。

## 面试会怎么问

**问：为什么一个“会用工具”的 Agent 在 GAIA 上仍可能得低分？** 答：工具调用只是中间动作。还需要正确拆题、检索可靠证据、跨源核验、处理图像与附件，并按精确格式交付。可用逐题轨迹把检索、理解、规划、执行、格式错误分开分析。

**问：怎样防止评测分数被误读？** 答：报告数据集版本和划分、题目数、运行日期、工具/人工参与情况、重复运行方差，以及原始失败样本。不要把课程旧截图或不同排行榜上的数字直接当作当前可比结论。
