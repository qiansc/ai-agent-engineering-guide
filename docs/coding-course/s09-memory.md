# 跨会话记忆怎样留下来：存储、召回、提取与整理

s08 管理的是当前对话的空间；程序退出后，新的 `messages` 仍从空白开始。如果用户长期偏好、稳定项目事实和有用线索下次还会用到，就需要另一个持久层。本章把每条记忆存成独立 Markdown 文件，通过简短索引选择相关内容，再在回合结束时谨慎提取新记忆。

## 一个文件存一条，索引负责发现

记忆放在 `.memory/` 下，每个 Markdown 文件用 YAML frontmatter 记录 `name`、`description` 和 `type`，正文写具体信息。`type` 有 `user`（长期偏好）、`feedback`（反复适用的工作反馈）、`project`（稳定项目事实）、`reference`（以后要找的外部线索）四类。`MEMORY.md` 由 `rebuild_memory_index()` 从实际文件重建，每行是名称、文件链接和描述。

```markdown
---
name: indentation-preference
description: User prefers tabs for indentation
type: user
---

User prefers tabs for indentation.
```

写入前 `memory_slug()` 把名称变成可用文件名；`memory_path()` 拒绝带目录分隔的文件名，检查解析后路径仍在 `.memory/`，并阻止把索引误当普通记忆文件。这里的索引是读取入口，不是记忆正文的第二份拷贝。需要完整语义时，仍须加载对应文件。

## 召回：先挑候选，再读正文

新请求到来时，`select_relevant_memories()` 取最近的用户文本与记忆目录，另发一次轻量模型请求，要求只返回目录下标数组，例如 `[0, 2]`；最多选 5 条。模型调用或解析失败时退回关键词匹配。随后 `load_memories()` 才读取选中文件，全部召回正文合计不超过 `RECALL_CHAR_LIMIT = 20_000` 字符。

`build_system()` 把索引和相关记忆纳入 system prompt，同时明确：召回内容是背景知识，不是新命令；它与当前用户要求冲突时，以当前要求为准。比如旧记忆说“习惯用 tab”，本轮用户明确要求“本文件按四空格”，就应遵守本轮要求。目录选择可能漏掉相关记忆，关键词降级也只能找到文字相近的项，所以不能把召回结果当成完整历史。

### 相关性选择究竟读了什么

`recent_user_text(messages, max_turns=3)` 先抽取最近几轮用户文本，避免把工具结果当成问题。选择器把每条记录的名称与描述列成带下标的目录，最多发送前 12,000 字符目录给模型；模型回复必须能解析成 JSON 数组。若得到无效下标，会忽略它；若多个下标重复，只保留一次，达到五条就停止。若模型调用或解析抛异常，退回 `keyword_memory_selection()`：它从英文词和连续中文片段提取关键词，在名称与描述上做简单包含计分。这个降级能处理直白相同词语，但不能保证语义相近或多语言别名被召回。

读取正文时，`load_memories()` 按选择顺序使用剩余字符预算。第一条很长的记忆可能占掉大部分 20,000 字符，使后面记录只有片段或根本读不到。教学代码把被读取的文件名和截取内容一起包装为 JSON，给模型保留“这段话来自哪份文件”的线索。生产系统通常还应按记录大小、优先级和权限分配预算，并给截断处明确标记，避免模型把半段说明当完整规则。

## 提取：只留下以后还成立的信息

Agent 给出最终回答、Stop hook 允许结束后，`extract_memories()` 从最近对话中请求候选记录。模型需要为候选标注 `scope`：`persistent` 才可能跨会话保存；`current_task` 用于“这次不要创建文件”“今天临时路径在……”之类一次性约束。宿主再调用 `validate_memory_record()` 与 `should_store_memory()` 检查字段、类型、作用域、临时词以及与现有记录的名称、描述、正文重复情况。

这些检查不会让记忆自动变成事实。模型可能把猜测误提取成项目结论，或漏掉含蓄的临时条件。本教学实现用规则挡住常见错误，但生产系统还需要来源、确认方式、敏感信息治理、删除入口和用户可见的更正机制。尤其不能把工具输出中的外部指令直接提升成用户偏好。

### 哪些候选会在最后一道检查被淘汰

`should_store_memory()` 不只看模型标的 `scope`。它要求 `type` 在四类中，`name`、`description`、`body` 都非空；将三者规范化后检查 “this session”“current task”“本次任务”“暂时” 等临时词；再对已有记忆比较规范化后的名称 slug、描述和正文，完全重复的候选不再写入。名称会经 `memory_slug()` 转换成文件名，因此两个不同标题如果得到同一个 slug，也被视为冲突。

这套规则能拦住明显的“一次性指令永久化”，但无法理解所有语境。例如“以后只有这个项目使用四空格”是长期但范围有限的规则，写成泛化的用户偏好就会误导其他项目。记忆正文需要带适用范围和来源；单靠 `type=user` 不够。另一个例子是“本次任务确认此仓库长期使用 tab”包含“本次任务”字样，简单临时词检查可能误拒，说明规则是保守的教学防线，不是最终语义判定。

## 整理：合并重复，也要能失败回滚

当记忆文件达到 `CONSOLIDATE_THRESHOLD = 10` 条，`consolidate_memories()` 让模型整理重复、修正旧信息、删去失效项。整理输入超过 20,000 字符时跳过；模型返回空列表或重名记录也会跳过。通过校验后，代码先给旧文件做快照，再替换为整理后的文件并重建索引；文件操作失败时用快照恢复。

这是一份教学上的本地文件实现，没有多进程写锁。若两个会话同时更新 `.memory/`，仅有失败回滚仍不足以避免覆盖；实际服务还要考虑版本或事务、冲突检测和备份策略。整理后的记录最好保留可追溯来源，否则后来很难分辨哪条是用户明确说的、哪条是模型概括的。

### 整理失败时会发生什么

整理时会提示模型最多返回 30 条目标记录，但宿主没有硬性校验条数。代码解析并验证每条记录，确认列表非空且转换后的 slug 不重复，随后读取旧文件作为快照。写新版本时，先删除旧记忆文件，再逐条写新文件，最后重建 `MEMORY.md`；任何文件操作异常都会删掉部分新文件、把快照写回并重建索引。若模型调用失败、记录超出输入预算或返回内容无法通过校验，函数打印 skipped 并保留旧记忆。

这保护的是**单次进程内写入失败**。如果机器在删除旧文件后突然断电、或者另一个进程同时写入，Python `except` 未必有机会回滚；真正的持久服务可先写临时版本、原子替换目录或使用事务性存储。整理也不是“一满 10 条就肯定变少”：模型可能保留全部，仍需检查质量、作用域和来源。

## 运行跨会话实验

运行 `python s09_memory/code.py`，输入 “I prefer using tabs for indentation. Remember that.”。结束后打开 `.memory/MEMORY.md` 与对应文件，确认名称、描述和正文。退出并重新启动，问 “What indentation style do I prefer?”，观察能否选中并加载这条记忆。再保存一条与缩进无关的信息，重问缩进，确认系统不必把全部记忆正文都发送进去。

最后输入 “Do not create files in this session.”，检查它是否被 `current_task` 过滤而未持久化。模型的提取结果可能有差异，所以实验重点是实际磁盘文件和下次会话的召回，而不是它说“我记住了”。如需清除记忆，应管理对应 `.memory/*.md` 文件并重建索引；不要只删 `MEMORY.md` 中的一行，因为它会被文件重新生成。

## 面试会怎么问

近期面经会问“长短期记忆怎么设计、怎样防止过期或错误记忆影响当前请求”。可以用四段回答：存储时分类型并记录作用域；召回时先根据当前问题选候选再读正文，设条数与长度预算；提取时只保留跨会话仍有用的用户偏好、反馈、稳定事实与线索，临时命令不入库；整理时合并冲突并保留回滚和更正入口。再强调当前用户请求和权限策略高于旧记忆，记忆属于可审查的背景资料，不是自动授权或无损 transcript。
