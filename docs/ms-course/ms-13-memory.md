# Agent 记忆：让它记得该记的，也能忘掉不该留的

用户前一轮问巴黎机票，下一轮说“那住宿呢？”Agent 应知道“那”指巴黎；隔了一个月，用户再次规划旅行，若曾明确保存“尽量不坐红眼航班”，系统也可以取出这个偏好。前者是会话上下文，后者是跨会话记忆。把所有聊天永久存起来并不是好记忆：需要确定保存什么、何时取出、如何更正和删除。

## 不同记忆解决不同时间尺度

| 类型 | 旅行示例 | 持续范围与实现提示 |
| --- | --- | --- |
| 工作记忆 | 当前请求、候选方案、未解决问题 | 一次任务内的草稿与状态，可放窗口外按需读取 |
| 短期/会话记忆 | “那住宿呢”承接前一轮的巴黎 | 一次会话的消息与摘要；进程结束后是否持久化由应用决定 |
| 长期记忆 | 用户同意保存的航班偏好 | 跨会话存储，需用户范围、更新与删除规则 |
| 角色记忆 | “滑雪专家”的稳定职责 | 多是指令和角色配置，不必伪装成模型自行形成的人格 |
| 情节/流程记忆 | 某次订票因无余票失败 | 记录任务步骤、结果与版本，供恢复或复盘 |
| 实体记忆 | 巴黎、卢浮宫、某次餐厅预订 | 结构化实体与关系，要核对提取是否准确 |
| 结构化检索记忆 | 从邮件中取航班日期、航空公司 | 将字段与原消息来源关联，支持精确查询 |

Microsoft Agent Framework 的 `AgentSession` 可通过 `agent.create_session()` 保持一段对话。重复使用同一会话能承接上下文，但会话结束或服务重启后是否恢复取决于序列化和外部存储；不能把内存对象本身当成永久用户记忆。长期偏好通常需要数据库或可检索索引，并按用户身份隔离。

## 一条记忆的完整生命周期

先**生成候选**：从用户明确表述或可靠业务事件提取，而不是把模型猜测写成事实。再**验证与存储**：给记忆一个用户、来源、时间、类型和适用范围。使用时按当前任务**检索与筛选**，避免把所有历史塞入提示。用户纠错或新偏好出现时**更新**，过期或撤回授权时**删除**。“遗忘”是管理的一部分；删除不仅是数据库删一行，还要考虑向量索引、缓存、摘要与副本中的残留。

例如用户说“上次坐红眼航班太累了”，候选记忆可以是“本次旅行优先避免红眼航班”，但不应自动推断“用户永远拒绝所有夜间航班”。可向用户确认是否长期保存偏好。以后用户说“这次可以坐夜间航班”，当前任务的明确指令应覆盖旧偏好；若用户说“以后都可以”，再更新长期记忆。记忆要能记录**冲突与覆盖**，不能只追加。

## Mem0 与 Cognee 各提供什么

`13-agent-memory.ipynb` 用 Mem0、Azure AI Search 与 Microsoft Agent Framework 实验记忆。Mem0 的流水线先从消息提取可能值得存储的信息，再决定新增、修改或删除；其后端可组合向量、图和键值存储。学习时重点看提取是否忠实、更新是否误覆盖、检索是否隔离不同用户，而不只看问答更流畅。

`13-agent-memory-cognee.ipynb` 使用 Cognee 将多种结构化和非结构化数据转为有嵌入支持的知识图谱，结合向量相似性与图关系检索，并展示图谱可视化。它适合探索“巴黎之旅—航班—酒店—用户偏好”等关系；如果任务只存几个明确字段，用普通数据库可能更简单。图谱里的关系仍需来源和纠错：模型抽取出“Ben 喜欢某酒店”时，应能回到原消息确认，不能因为图谱可视化漂亮就把推断当事实。

Azure AI Search 可承接大规模可检索记忆或用户资料索引。相比只按语义相似度找聊天片段，结构化记忆可按用户、日期、目的地、航班号等字段过滤；对“我星期二订了哪趟巴黎航班”这样的查询尤其有用。结构化 RAG 的检索能力很强，但准确性仍依赖解析、索引和权限，不能声称天然达到某种“超越人类”的召回。

## “知识代理”是否真能自我改进

还可以设计一个旁路角色：观察主 Agent 对话，识别有价值信息，提取与总结后存入知识库，未来查询时再取回。这是一种记忆更新架构，不等于主模型自动学习。可先用规则和廉价模型判断是否值得保存，再在必要时调用更强提取器；旧而少用的内容转冷存储以降成本。

该架构的危险在于错误、隐私和跨用户污染。把助手自己编造的航班写入长期知识，未来会反复被引用；把 A 用户订单记给 B 用户是严重隔离问题。写入前应检查来源是用户确认、真实工具结果还是模型输出；长期存储前进行权限与敏感数据处理；读取时再次检查租户与用户范围。对每条取出的记忆，保留来源 ID 和更新时间，让模型能处理“资料可能过时”。

## 练习：让一条偏好有来有去

从三轮对话中抽取“预算 5000”“本次偏好直飞”“用户不喜欢太拥挤”的候选。给每条标记是否跨会话保存、为何保存、如何向用户展示与删除。下一轮用户把预算改为 6000，确认旧预算被覆盖；再让另一位用户问相同问题，确认检索不会拿到第一人的偏好。最后模拟索引延迟：主数据库已删除的偏好仍在向量索引里，系统应如何暂时阻止它进入模型上下文？

## 面试会怎么问

小红书面经问长短期记忆，百度实习面经问长期记忆，影石创新面经问记忆与压缩。回答时从使用场景分工作状态、会话历史与跨会话记忆，讲清写入依据、检索过滤、过期/冲突处理和用户删除。若面试官问“向量库是不是记忆”，说明它是检索存储的一种，不负责决定哪些事实值得长期保存或是否可信。
