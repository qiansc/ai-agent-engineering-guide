# 设计一个愿意让人长期使用的 Agent

Agent 会主动查找、提醒甚至替用户行动。因而体验设计不能只考虑“这句话答得像不像人”，还要考虑它什么时候出现、展示了什么依据、用户怎样纠正它，以及用户不想继续时能否停下。可以从三个角度看这些问题： Agent 所在的空间、它经历的时间和建立信任的核心机制。

## Agent 活在什么空间

所谓“空间”，是用户、设备、平台、其他人和外部服务共同构成的环境。旅行 Agent 可能在手机上收集偏好，在网页上展示候选行程，在航班价格变动时发送提醒。设计时第一条是让它**连接人、事件和可用知识**：它可以帮助用户找到合适航班、联系同行者、理解签证条件，但不应把人的决定藏在系统后面。Agent 应容易被授权用户访问，同时不必每时每刻抢占界面。

“后台运行、适时出现”需要具体规则。比如价格下降提醒只有在用户订阅某航线、价格满足阈值、提醒没有过度频繁时才触发；重要的行程取消不能只躺在日志里。用户要能看见当前是否在监控、最近检查时间、数据来源、关闭入口和通知渠道。语音、文本等多模态输入输出，选哪种应看场景与无障碍需求，不必为了显得先进而强制语音。

## 它怎样跨越过去、现在与未来

**过去**不是“尽量保存所有聊天”。Agent 可以用明确保存的历史偏好改善建议：用户曾选择直飞、避免红眼航班，这些可作为候选过滤条件。但偏好可能变化，数据需要出处、更新时间、可修改和删除的入口。某次为省钱选择转机，不等于永久喜欢转机。

**现在**强调有用的引导，而不只是广播通知。航班延误时，Agent 可以把相关的转机风险、备选航班和用户可做的操作放在一起；若它只能重复航空公司通知，就没有增加多少价值。“交互渐进”可以理解为先给最重要的选择，再让用户展开细节，避免初次见面就要求填写一长串偏好。

**未来**是适应变化：用户换设备、改出行习惯、需要更大的字体或改用语音时，Agent 应保持关键状态一致，允许重新设置交互方式。这里的“适应”不是未经授权地长期推测用户。任何偏好自动化都要有用户可理解、可撤回的依据。

| 设计维度 | 旅行 Agent 的具体问题 | 可检验的设计结果 |
| --- | --- | --- |
| 空间 | 在手机后台查价、网页上确认预订，谁能看到什么？ | 每个入口显示权限、运行状态、通知设置 |
| 过去 | 记住了哪些偏好？过期与删除怎么办？ | 用户可查看、修改、删除保存项 |
| 现在 | 何时打断用户？何时先提供选项？ | 通知阈值、确认点和“稍后处理”明确 |
| 未来 | 偏好与设备变化如何处理？ | 设置可迁移，可重新选择交互方式 |
| 信任 | Agent 做过什么、没做什么？ | 轨迹、来源和最终动作状态可见 |

## 把信任做成界面行为

落地时抓住三个指导原则：**透明度、控制、一致性**。透明度意味着开始使用时说明 AI 参与、能力和限制；发生重要操作后能看到历史动作；用户能反馈和纠错。控制意味着用户能设偏好、修改行为边界、关闭自动化，并要求系统忘记相关数据。一致性意味着同一个上传、语音或分享动作，在不同屏幕采用用户熟悉的图标和反馈；状态也不能在手机上显示“已完成”、网页上却显示“处理中”。

设计旅行 Agent 时，可以在首次使用展示两个示例请求，而不是长篇技术说明；在候选行程旁显示价格获取时间和“重新查询”；在预订前把城市、日期、乘客、总价、取消规则和即将发生的副作用列清楚，让用户逐项确认。预订完成后给出真实订单号；失败时显示尚未完成的事项。这些界面细节直接影响信任，比把系统提示写成“请诚实可靠”更可验证。

不确定性要如实呈现。模型推测“这趟转机可能来得及”，系统应检查机场转机最低时长与航空公司规则；查不到时就说无法确认，不能用肯定语气填空。“接受不确定性、建立信任”是设计核心，工程上要通过来源、状态、确认和回退来兑现。

## 练习：为一个主动提醒画用户旅程

选择“用户希望监控未来一个月内去东京的直飞机票”作为练习。从授权监控开始，依次写出设置条件、后台检查、达到阈值时的提醒、用户打开详情、最终确认与关闭监控。每一步回答四个问题：用户看得见 Agent 在做什么吗？这一步读了哪些数据？它能直接写入或付款吗？如果数据过期或工具失败，界面显示什么？

再找一个人只看你的页面草图，让他指出怎样删除偏好、怎样知道机票是否真的买到、怎样阻止下一次提醒。若这些入口找不到，就算回答质量很好，产品仍缺少控制。

## 面试会怎么问

TikTok AI Agent 开发面经提到会议转写项目的隐私与评测；美团 9 月 AI Agent 面经追问长流程中的幻觉与确认。若面试官问“怎么让用户信任 Agent”，可以按本章三个设计原则回答，并落到一个具体流程：告诉用户 AI 何时参与、引用或显示输入来源；对重要动作给确认与状态；允许纠错和停止；用失败样本检查用户是否被误导。不要把“界面友好”当作抽象形容词，要说清按钮、状态和记录。
