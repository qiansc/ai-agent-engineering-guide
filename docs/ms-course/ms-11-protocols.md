# MCP、A2A、NLWeb：工具、代理与网站分别怎样接入

旅行助手若要查航班，可以连接提供工具的 MCP server；若要把酒店研究交给另一家公司维护的独立 Agent，可以使用 A2A；若旅行网站希望人和外部 Agent 都能自然语言查询站内目录，NLWeb 提供一条实现路径。三个协议解决的连接问题不同，项目里可能同时出现。

| 协议 | 主要连接 | 对外提供什么 | 旅行例子 |
| --- | --- | --- | --- |
| MCP | AI 应用与工具/资源服务 | 工具、资源、提示模板 | 查航班、读取政策、请求预订动作 |
| A2A | 一个 Agent 与另一个独立 Agent | 能力发现、任务、消息、进度和产物 | 总旅行 Agent 委派酒店 Agent |
| NLWeb | 网站内容与自然语言访问者 | 站内问答/搜索接口，可通过 MCP 暴露 | 问旅行网站“有泳池的亲子酒店” |

## MCP：主机、客户端、服务器

MCP 的主机是承载模型交互的应用，例如 IDE；主机为每个 MCP server 建立一个对应客户端连接。Server 独立暴露能力，客户端通过协议发现并调用。Server 能力分为三类：**工具**是可执行函数，可能读也可能写；**资源**是供应用读取的内容，例如文件或记录；**提示**是预设的交互模板。工具描述包含名称、作用与输入 Schema，模型据此提出调用，宿主仍负责授权和策略。

看一个航班例子：旅行助手连接航空公司 MCP server，发现 `search_flights` 与 `book_flight` 等工具；用户请求波特兰到火奴鲁鲁的航班，模型选择搜索工具，Server 包装内部预订 API 返回候选；用户选中后才考虑预订工具。这里的“连接成功”仅证明可发现接口，不证明每位用户都有购票权限。MCP 可以减少为每种服务手写不同适配器的成本，但 Server 的身份、数据访问和工具副作用仍必须逐个审查。

“标准化安全”不应理解为协议自动保证安全，更准确地理解是协议让能力发现与连接方式有共同结构；真正安全仍取决于所用传输、认证、主机的同意与授权策略，以及 Server 的实现。动态发现也不是“发现了就全部交给模型”：应用应按任务与用户权限筛选可用工具。替换底层 LLM 通常更容易复用同一 MCP 集成，但不同模型对工具描述的理解与调用质量仍要重新评测。

## A2A：把完整任务交给另一位代理

MCP 工具通常暴露相对明确的动作，A2A 面向另一个可能内部有自己模型、工具和运行状态的独立 Agent。**Agent Card** 用于发布名称、描述、技能、端点、版本与流式/推送等能力；调用方可据此发现适合处理酒店、航班或租车的 Agent。消息发给远端后，任务可能立即给答案，也可能持续运行并产生状态更新和最终 **Artifact**（文本、结构化数据或文件）。

再看执行器与事件队列：远端 Agent 接到任务上下文，使用内部工具工作；任务较长时不能假设 HTTP 连接会一直维持。现行 A2A 规范提供查询任务状态、流式订阅和推送通知等不同更新方式，具体能力以 Agent Card 声明为准。不要把“工件发送后连接关闭”理解为固定规则；实际可能是直接 Message、带状态的 Task、流式更新或后续查询，不能把一种示意当成所有实现。

总旅行 Agent 若并行委派三家服务，必须给每个下游角色明确日期、人数、预算、地点和禁止动作。三个服务即使都返回“完成”，也需要核对机票到达日期与酒店入住日期是否一致、租车取车时间是否可行、哪个服务真正下了单。跨组织委派时，还要限制传给远端的个人资料，给任务 ID 和追踪 ID，避免重复投递产生重复预订。远端 Agent 使用什么模型可以独立选择，这不改变委派方对最终用户的责任。

## NLWeb：让网站目录能被自然语言访问

NLWeb 包含自然语言查询服务、协议化 JSON 响应、网站内容的嵌入和向量检索，以及可供外部 Agent 使用的 MCP `ask` 能力。旅行网站可将酒店、航班或套餐目录以 Schema.org 等结构化形式提供，摄取后建向量索引；用户问“下周火奴鲁鲁有泳池的亲子酒店”，服务检索目录，按地理位置、设施和日期筛选，并以自然语言或结构化结果返回。外部旅行 Agent 也能通过该网站开放的 `ask` 入口查询。

这只是“发现与问答”能力的基础。酒店是否下周有房、价格是否有效，要看源目录是否包含实时库存及更新机制；向量相似度不能替代日期和设施的精确过滤。NLWeb 可以返回 Schema.org 结构化信息，具体字段与 JSON 形状依所用实现和版本核对。当前官方实现提供 `/ask` 和 `/mcp` 端点，两者是同一站点能力的不同接入方式；网站仍应决定哪些内容公开、如何更新索引和返回来源。

## 选协议时问四个问题

首先问对方是窄工具、完整独立 Agent，还是网站内容。其次问请求是否有写入副作用；若有，用户确认、身份和幂等由谁负责。第三问交互是一次返回还是长任务；若长任务，选择轮询、流式或推送，并处理断线重连。最后问如何验证结果：MCP 工具返回真实状态，A2A 产物带任务与来源，NLWeb 结果可回到网站原条目。协议标准化通信，不自动标准化业务正确性。

## 练习：画出一次旅行委派

用一个 MCP `search_flights`、一个 A2A 酒店 Agent 和一个 NLWeb 旅游网站目录设计行程查询。写出给每个服务的输入、收到的字段、可信程度与失败回退。让酒店 Agent 超时、NLWeb 返回去年酒店介绍、航班工具返回价格但无货币单位，检查总 Agent 是否能停下来说明缺口，而不是拼出“全部已预订”。

## 面试会怎么问

百度 Agent 实习面经问 MCP transport，Raytheon 复盘涉及 A2A。回答 MCP 与 A2A 区别时，不要只说“一个接工具、一个接 Agent”；补充发现对象、消息/任务状态、远端自主性与安全责任。若追问 transport，先解释本地进程与远程服务在连接、认证、超时和重连上的差异，再说明具体项目选型。若用户目标只是查站内资料，NLWeb 或普通搜索接口可能足够，不必再套一个独立 Agent。
