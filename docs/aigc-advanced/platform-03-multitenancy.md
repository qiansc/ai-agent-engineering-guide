# 多租户权限与 Agent Marketplace 的治理

企业 Agent 同时代表用户行动，又有自己的工具、凭证、记忆和任务状态。平台不能只问“这个用户有权限吗”：同一用户可能启动不同风险等级的 Agent，同一 Agent 也可能为不同用户服务。一次调用需要同时核对用户、Agent、任务、工具、资源、参数、环境和授权时效。

## RBAC、ABAC 与租户隔离

RBAC 用角色管理基础平台操作，例如谁能创建客服 Agent；ABAC 根据数据等级、部门、地域、任务风险和时间做更细粒度决定；租户隔离保证不同客户的知识、记忆、trace、工具配置互不可见。三者互补，而非择一。

工具调用应携带 `user_id`、`agent_id`、`tenant_id` 和 `task_id` 等上下文。RAG 和 Memory 在召回前先做权限过滤，不能先全局语义检索、再依赖模型不引用越权片段。审计和 trace 本身也要按租户隔离并脱敏。高风险工具调用在策略检查后再进入审批。

例如财务经理有查看财务数据的权限，但他启动的客服 Agent 不应自动继承所有财务权限。本次客服任务还必须满足 Agent 能力、工具访问范围、数据用途及必要审批。用户身份说明谁发起，Agent 身份说明哪个自动化主体执行；两者分开才能判断责任与限制权限放大。

## 以 Agent 身份受控代理用户

推荐每次调用同时记录用户和 Agent 身份，Agent 使用限定作用域的凭证。需要代表用户操作时，明确 on-behalf-of 的资源和动作范围，高风险写操作再次确认。Agent 默认权限不大于用户权限，而且当前任务可进一步收窄。凭证尽量短期化，任务结束撤销临时授权；禁止让共享 Agent 持有无限期个人 token。

## 私有化部署不是只搬服务器

私有化要确定模型走公有 API、私有模型还是混合路由；文档、代码、trace、记忆能否出域；如何对接 SSO、LDAP、OIDC 和企业 IAM；网络采用内网、VPC、专线还是代理。工具要接数据库、工单、Git、IM、邮件；运维还要覆盖算力、队列、镜像与插件安全扫描、离线升级、灰度、回滚、备份和灾备。很多项目难点不在推理接口，而在客户系统集成、权限和运维责任。

## Marketplace 怎样避免堆满不可用资产

Agent Marketplace 管可复用的 Agent；Skill Marketplace 管工作流程与能力包。每项资产应说明适用场景、owner、输入输出、所需工具与数据权限、风险等级、版本、示例任务、评测结果、安全审核和支持方式。

上架流程可以是提交→自动检查元数据及依赖→功能与安全评测→高风险人工审核→小范围灰度→根据反馈和 trace 正式发布。下架同样要有规则：owner 失联、工具依赖失效、评测回归、发现安全风险、成本不可接受或业务规则过期。Marketplace 的质量来自维护责任与可评测性，不是卡片数量。

## 面试会怎么问

**RBAC、ABAC、租户隔离怎样落地？** 分别说角色、细粒度属性和数据边界，再补“检索前过滤”和 trace 隔离。

**为何分开用户与 Agent 身份？** 用财务经理启动客服 Agent 的例子解释权限放大，并指出凭证、审批与审计如何绑定双重身份。

**私有化和 Marketplace 怎么设计？** 私有化从数据出域、身份网络、工具集成、运维升级说；Marketplace 从上架评测、权限和下架治理说。
