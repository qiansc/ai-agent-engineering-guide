# 长期运行 Agent 的安全边界、Checkpoint 与行为观测

自进化、多平台的 Agent 会接收来自不同渠道的消息，长期保存知识，还可能编辑文件、执行命令、安装插件。风险并不集中在模型的一次回答里，而分布在入口身份、会话隔离、工具动作、后台维护和跨平台发信之间。安全必须由 Runtime 在执行前检查，不能依赖模型“自觉遵守”。

## 先画清几个边界

入口需要验证用户和平台消息来源；Session、Workspace 与租户要隔离；工具调用应结合用户、任务、目标资源、参数与风险审批；文件和命令执行要在受控环境；Memory/Skill 更新需要来源与版本；插件只能使用声明的权限；日志和轨迹要脱敏；高风险变更要有恢复路径。一个环节放松，别的环节不能自然补救。

## 文件、命令与循环分别拦什么

文件安全针对路径与内容：敏感凭据、Shell Profile、系统配置和 Agent 自身密钥目录不应被随意写入。检查应考虑允许根目录、规范化真实路径与符号链接，避免看起来在安全目录内的路径实际指向别处。

命令安全针对 Shell 动作：按只读、写入、联网、安装、危险与破坏性分类，结合工作区与用户授权决定放行、审批或阻断。仅看命令字符串可能不足以判断脚本副作用，需要沙箱、资源和网络限制辅助。

Tool Loop Guardrails 看的是**一串动作**：同一只读工具反复调用没有新信息、相同参数连续失败、在两个工具间来回切换却不推进状态。可以先警告模型，再要求换策略、停止或人工接管；同时限制轮数、时间和成本。它不替代单次文件与命令安全。

例如 Agent 连续五次用同样参数搜索仍无新结果，应触发无进展检测；尝试写入敏感密钥路径则应立即被文件安全阻断。若用户确有高风险合法需求，审批系统记录批准范围；Trace 让事后能区分模型请求、宿主许可和外部实际效果。

## Worktree、Checkpoint、Rollback 各解决什么

编码场景可让每个 Agent 会话在独立 Git Worktree 中探索，减少并发 Agent 互相覆盖及用户 Dirty Worktree 被误改；最后选择和审查 Patch。Checkpoint 在高风险编辑前记录文件或状态快照及工具调用前后 diff。Rollback 按任务、文件或安全点恢复错误修改。格式化、批量替换、依赖升级和迁移脚本前，保存可恢复点尤其有用。

并非所有只读任务都要做重型 Checkpoint。回滚本身也要审计，防止恢复操作覆盖用户后续改动。更重要的是，本地文件回滚不能撤销已经发出的邮件、支付或生产 API 请求；这类外部副作用需要幂等键、补偿事务或人工处理。

## 观测要能服务排障，也要尊重隐私

Trace 可记录平台、频道、用户/工作区范围、Session/Task ID、模型和 Provider、命令、工具结果、Skill 与 Memory 使用、上下文压缩、后台事件、审批、Token/成本/延迟、错误重试和插件事件。指标可帮助找到低效工具链、常用 Skill 和维护候选资产；也可以生成用户使用洞察。

行为画像应本地优先或严格租户隔离，敏感内容脱敏，允许用户关闭、导出和删除。娱乐化“成就”不能凌驾于安全和隐私之上。观察系统需提供按 Run 钻取的事实，但不能把完整用户对话默认发给不相关的分析者。

## 面试会怎么问

**问：自进化多平台 Agent 的安全边界怎么设计？** 从入口身份、会话隔离、工具权限、文件/命令、知识写入、插件、日志和恢复画层次，讲一个高风险动作如何逐层获准。

**问：文件安全、命令安全、Tool Loop Guardrails 有何区别？** 前两者拦单次动作，后者识别行为模式；用敏感路径写入和重复搜索示例说明。

**问：为什么需要 Worktree、Checkpoint、Rollback？** 用用户未提交改动与自动编辑说明隔离/恢复价值，同时指出生产外部副作用无法靠本地 Git 回滚。

**问：多平台如何观测？** 给出 Session/Task/Tool/Approval 的 Trace 主线，再讲租户隔离、脱敏与用户控制。
