# 从离线评测到上线：CI、Shadow Mode 与失败回流

Agent 的一次发布不只可能改代码，还可能更换模型、Prompt、工具 schema、MCP Server、Memory Policy、RAG 索引、Guardrail、Workflow 或权限。任何一种改动都可能让旧任务退化。把 Harness 接入交付流程，就是让每个版本先在固定任务集里接受检查，再逐步承担真实流量。

## 分层评测各做什么

| 层级 | 目标 | 触发时机 | 典型阻断 |
| --- | --- | --- | --- |
| Smoke Eval | 快速发现明显不可用 | 提交、Prompt/Tool 变更 | 核心任务不能运行 |
| Regression Eval | 防止历史失败复发 | PR、发布前 | 关键场景相对基线退化 |
| Safety Eval | 检查越权、泄密、注入与危险动作 | 发布前、策略/权限变更 | 高危样本失败 |
| Robustness Eval | 检查工具异常、网络错误、用户反悔 | 定期或重大变更前 | 恢复或停止机制失效 |
| Shadow Eval | 用真实分布旁路观察新版本 | 生产观测阶段 | 新版本计划出现高风险偏差 |
| Canary Eval | 让新版本承担少量真实责任 | 灰度阶段 | 线上目标指标触发回滚 |

Smoke 应小而快，Regression 包含历史失败和核心业务，Safety 独立维护红队集；Shadow/Canary 则帮助看见离线样本没有覆盖的真实分布。规模取决于业务，不应把某个示例数量当成通用门槛。

## 发布门禁怎样落地

一个常见顺序是：变更触发 Smoke；通过后运行 Regression 和 Safety；与同配置基线比较质量、安全、成本和时延；决定是否进入灰度；灰度期间收集 Trace 并设回滚条件；线上失败再回流到评测集。

门禁可以规定 Smoke 全过、高危安全失败为零、回归下降不能超过某个阈值、成本和 P95 时延不得越界。原始材料给出“回归不降超过 1%、平均成本不增超过 20%”作为示例，实际阈值需根据样本数量、方差、业务风险和既有 SLA 确定。对于高危越权，通常不宜用一个平均分掩盖单次失败。

报告至少同时呈现总体变化和按任务类型/风险层级的变化。一个版本总体成功率提升，却在支付或删除场景退化，应被阻断或缩小权限。门禁不仅要告诉团队“失败”，还要链接到失败 Run、差异轨迹和环境快照。

## Shadow 与 Canary 的责任边界

Shadow Mode 让新版本看到真实请求，但其写操作进入 mock、dry-run 或隔离环境，不影响真实用户。可以比较旧/新模型的答复、工具计划、成本和安全风险，记录高风险动作而不执行，并抽样人工复核差异。要注意旁路环境与真实环境可能不完全一致，因此 Shadow 结果不能证明生产副作用安全。

Canary 则让新版本服务少量真实用户或低风险任务。它会承担真实责任，所以需要明确流量选择、版本组合、Guardrail 命中监控、异常 Trace 标注和自动/人工回滚条件。Shadow 回答“在真实分布下会怎样计划”，Canary 回答“在受限真实责任下能否稳定交付”。

## 把线上失败变成新的回归任务

失败从用户反馈、人工接管、事故复盘或线上 Trace 进入。先分类：理解、上下文、工具、权限、策略或环境故障；再清理敏感信息，固化初始状态、用户输入、可用工具与期望结果，写成可复现 Task Spec。把任务放到 Regression、Safety 或业务专项集，针对失败源修 Prompt、工具、检索/记忆、Policy 或产品澄清流程，最后重跑 Harness。

例如 Agent 因工具返回结构变化而误读字段，正确修复可能是工具 schema 与错误处理；只在 Prompt 里补一句“请注意字段”既脆弱也难验证。用户目标本来含糊，则应改交互澄清，不必强迫模型猜测。回流闭环应让评测集变强，同时避免把同一偶发噪声无限重复采样。

## 面试会怎么问

**问：Harness 怎样接入 CI/CD？** 从变更对象开始，讲 Smoke → Regression/Safety → 基线比较 → Shadow/Canary → 监控回滚。用“Prompt 更新可能触发工具调用变化”说明为什么代码检查不够。

**问：Smoke、Regression、Safety、Canary 怎么分层？** 给每层目标和触发时机，补 Robustness 与 Shadow 的作用。若追问发布阈值，说明按风险与统计波动设定，不能死背示例数字。

**问：如何持续优化？** 用一条真实失败从 Trace、脱敏、环境固化、分类、修复到回归验证的链路，强调修问题发生的层，而非一律改 Prompt。
