# Trace 与 Grader：看清 Agent 为什么成功或失败

一条最终答案很难说明 Agent 的工作质量。它可能经过错误的工具调用后碰巧给对答案，也可能因外部 API 超时而失败，却被错误归因到模型。Trace 把每一轮模型决定、工具执行、权限判断和环境变化串起来；Grader 在这些事实之上判定结果和过程。两者共同让评测报告有可解释性。

## Trace 应记录哪些事实

从用户输入到最终 Artifact，至少记录：输入消息与系统/开发者/策略版本；每次模型调用的参数、输出与 Token；工具名、参数摘要、返回、错误和耗时；权限申请及批准/拒绝；RAG 检索结果与 Memory 读写；子 Agent handoff；数据库、文件或页面状态变化；Guardrail 命中；最后答复与产物。

这些信息最好由同一 `run_id` 串联，每个步骤带时间和父子关系。工具参数与检索结果可能含个人信息或密钥，记录时要做必要脱敏和权限控制。保留“是否调用、结果怎样”不等于可以把所有原始负载公开给评测看板。

Trace 有四种用法：Debug 用它定位失败步骤；Grading 用它检查过程是否合规；Audit 用它追溯谁批准了动作；Dataset Mining 用失败轨迹构造新样本。只记录最终回复，会同时丢掉这四种能力。

## 五类评分各回答一个问题

| 评分 | 看什么 | 示例 |
| --- | --- | --- |
| Outcome | 答案或最终 Artifact | 报告是否回答问题，Patch 是否解决缺陷 |
| Trajectory | 计划、工具、审批、中间观察 | 是否绕过审批，是否重复无效调用 |
| State | 环境最终状态 | 订单是否进入待审核，文件 diff 是否符合范围 |
| Safety | 禁止动作和敏感信息 | 有无越权查询、泄密、误执行 |
| Cost | Token、时延、工具和人审成本 | 每个成功任务的成本及 P95 延迟 |

以编码 Agent 为例，测试通过是 Outcome 的强证据，但不是全部：Patch 可能修改无关文件，或覆盖用户未提交内容，需同时看 Trajectory、State 和 Safety。客服 Agent 则可能话术正确而数据库状态错误。浏览器 Agent 点击前没有确认就支付，也不能因为页面显示“成功”而通过安全评分。

## 判分器要组合使用

确定性规则适合检查字段、权限、调用次数和禁止动作；单元或集成测试适合检查代码功能；状态比较适合业务系统；LLM-as-Judge 可以评估摘要忠实度、答复完整性和沟通质量；高风险案例需要人工复核。各方法各有边界：规则容易漏掉开放式语义，测试可能不完整，模型裁判有偏差、可能受被评内容注入，人工成本高。

一个稳妥顺序是：先把能直接验证的东西做成规则、测试和状态比较；开放式质量由模型裁判补足，并对裁判本身做样本校准；金融、医疗、法律、合规或重大权限变更保留人审。别把“模型觉得合理”当成安全规则的替代品。

评分还应输出**失败标签**。例如“工具参数错误”“权限拒绝”“检索没找到政策”“环境超时”“模型推理偏离”，这些标签决定下一步修工具、修上下文、调策略还是改模型。一个总分不足以指导改进。

## 报告该展示什么

| 维度 | 建议指标 | 使用时注意 |
| --- | --- | --- |
| 任务质量 | success rate、pass@1、pass@k、state match | `pass@k` 要说明多次尝试口径 |
| 稳定性 | 多次运行方差、一致性、重试成功率 | 避免只展示最好的一次 |
| 工具 | 成功率、参数错误率、无效调用率 | 区分模型选错与工具本身故障 |
| 轨迹 | 平均步骤、循环率、handoff 成功率 | 步数少不一定好，要结合结果 |
| 安全 | 越权、注入成功、泄密、高风险确认 | 同时看误放行和误拦截 |
| 成本与时延 | Token、每成功任务成本、平均及 P95/P99 时延 | 成本下降不能掩盖质量退化 |
| 回归 | 新旧版本按任务类型的提升和退化 | 聚合平均值会遮住少数高风险失败 |

线上再加人工接管率、回滚率、Trace 覆盖率与数据泄露事件。报告应允许从异常指标点进单条 Run，而不只是给一张漂亮的趋势图。

## 面试会怎么问

**问：为什么要完整 Trace？** 用一次“最终答复正确却越权查单”的具体轨迹讲清 Debug、Grading、Audit 和失败回流。

**问：Outcome、Trajectory、State Grading 怎么区分？** 分别说用户可见结果、中间动作和外部系统的最终状态，再补 Safety/Cost 是横向约束；给编码或退款例子。

**问：规则、测试、LLM-as-Judge 和人审怎么配？** 能确定性检查先确定性检查，开放式质量再用模型，人审处理高风险与不确定样本。若追问模型裁判偏差，要说样本校准与复核。

**问：要看哪些指标？** 按质量、安全、稳定性、成本、时延、回归分类，并强调每个指标可追溯到 Run 和失败标签。
