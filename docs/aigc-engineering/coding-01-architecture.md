# 编码 Agent：从补全代码到交付工程任务

你在 IDE 里接受一段补全，只需要判断这段代码能否用；把一张修复工单交给编码 Agent，系统则要找到相关文件、理解已有改动、编辑、运行测试，并把结果交还给你审查。两者都用模型，但责任范围不同。编码 Agent 的价值来自这条可验证的工作链，而不只是一次生成的代码更长。

## 一张工单怎样走完

以“修复订单列表分页重复”为例。Agent 先读用户描述和仓库规则，搜索分页组件、接口参数和相关测试；定位后形成修改计划，查看当前 `git diff`，避免覆盖尚未提交的用户改动。修改代码后，它运行对应单测、类型检查或构建；如果测试失败，读取失败日志，决定是代码错误、测试数据过期，还是需求理解有误。最终交付物至少包括改动文件、关键 diff、实际跑过的检查与未解决问题。

这条链可以写成：需求理解 → 仓库探索 → 计划 → 编辑 → 验证 → 修正 → 交付。每一步都有外部事实可查。模型说“已经修好”不代表测试通过；只有运行时看到测试结果、文件状态和可审查的 diff，才可以把工单标为完成。

## Copilot 与编码 Agent 的工作边界

| 维度 | 补全式 Copilot | 编码 Agent |
| --- | --- | --- |
| 用户交代的内容 | 光标附近要写什么 | 一项工程目标和约束 |
| 主要上下文 | 当前文件、选区、局部引用 | 仓库、历史、规则、工具观察 |
| 系统动作 | 建议代码，用户应用 | 搜索、编辑、执行命令、检查结果 |
| 验证责任 | 主要由用户承担 | Agent 可以执行，用户仍审查高风险结果 |
| 典型风险 | 建议代码有错 | 还可能改错文件、运行危险命令、泄露信息 |

“像初级工程师”只是帮助理解交互方式，不是权限承诺。Agent 可以有较大自主性，但工具能力和审批范围仍由宿主程序、沙箱和用户控制。

## 典型系统有哪些层

一个终端或 IDE 编码 Agent 可以按八层理解，但实现中这些层未必对应八个独立服务。

| 层 | 处理的事 | 交付给下一层的内容 |
| --- | --- | --- |
| 入口 | CLI、IDE、Web、SDK 或远程会话接收任务 | 用户目标、工作区和交互事件 |
| 会话 | 维护 session ID、消息、配置、预算与权限模式 | 可恢复的任务状态 |
| 上下文 | 收集项目规则、Git 状态、关键文件、历史摘要 | 当前轮真正需要的输入 |
| 模型循环 | 发起模型调用，接收工具请求或最终答案，控制重试与终止 | 待校验动作 |
| 工具 | 读写文件、搜索、Shell、Git、LSP、Web、MCP 等 | 真实观察和产物 |
| 权限 | 根据主体、动作、参数与环境批准或拒绝 | 可执行的调用决定 |
| 交互 UI | 展示 diff、进度、成本、错误和审批请求 | 用户反馈 |
| 观测与持久化 | 保存 trace、成本、诊断、检查点 | 回放和恢复依据 |

模型循环与工具执行之间要留一个清晰断点：模型只提出动作，宿主验证参数、权限和副作用后执行。会话层与文件系统也不能彼此代替；聊天摘要可能声称已编辑某文件，恢复时仍要重新检查该文件和 `git diff`。

## 为什么软件工程是有利场景

仓库、Shell、Git 与测试框架已经为 Agent 提供相对清晰的可操作环境。编译、lint、类型检查和测试会返回可观察反馈；开发者也习惯审查 diff。因此修 bug、补测试、重构、文档、代码审查都有明确的尝试路径。不过“反馈可验证”不等于“所有修改都能靠测试证明正确”：缺失的测试、错误的需求和不合理的架构改动仍需人审。

开始做原型时，可先选一张有现成测试的小工单，把每一步的输入、工具调用、权限判断、测试输出与最终说明记录下来。它比只展示一次成功截图更能说明系统哪里可靠、哪里需要人工接手。

## 用任务轨迹检查架构是否真的完整

在上述分页 bug 中，可以给每个关键事件分配同一 `run_id` 下的 `step_id`：搜索定位、文件读取、编辑请求、编辑结果、测试请求、测试结果、最终说明。若测试进程退出码为 1，UI 不应只展示“Agent 正在思考”，而应显示失败的检查；会话层也要把失败写入状态。若模型因上下文不足重复读取相同文件，观测层应能指出浪费发生在哪里。若用户拒绝了写入审批，模型循环必须收到明确拒绝观察，不能继续假装补丁已应用。

这也给产品设计一条验收线：用户应能随时看到当前目标、已改变的文件、正在等待的审批和已经跑过的验证。CLI 与 IDE 的展示形式不同，但背后应消费同一份任务状态。这样从终端切到 IDE 或断线重连时，进度不会因为界面重建而丢失。

## 面试会怎么问

百度 Coding Agent 三轮复盘追问了 ReAct、Skill 误调用、上下文隔离和密钥保护；字节 Agent 秋招复盘问到 AI-native Coding 与具体 Harness。若面试官问“编码 Agent 与 Copilot 有什么区别”，先说明工作单位从代码片段变成可验证工单，再沿上表讲架构和新增风险。若追问“为什么你这个场景适合 Agent”，用一条自己实际做过的探索—编辑—测试轨迹回答，并说明哪些步骤必须人工确认。这里给的是准备思路，不能代替候选人自己的项目经历。
