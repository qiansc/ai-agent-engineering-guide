# AgentOS 的安全与长任务生命周期

一个长任务可能由用户消息触发，也可能来自 Cron 或 Webhook；执行中会调用模型、等待工具、请求审批、压缩上下文，还可能被用户打断。要让它可靠运行，安全边界与任务状态必须写在程序里，不能依赖模型每轮“记得”怎么做。

## Sandbox、Tool Policy 与 Elevated 分别管什么

| 控制 | 回答的问题 | 举例 |
| --- | --- | --- |
| Sandbox | 在哪里执行、能访问什么资源 | 只读容器、受限工作区、远程主机 |
| Tool Policy | 哪些工具与参数被允许 | 可读文件，写文件需审批，禁止发外部消息 |
| Elevated | 是否允许临时越出通常的执行限制 | 经明确批准后使用宿主机权限 |

允许调用 `bash` 不等于允许它访问宿主机；在容器内运行也不保证命令没有危险；提权不应自动解锁其他工具。Deny 规则应优先于普通 Allow；当 Allow 列表为封闭集合时，未列出的工具不可用。Docker socket、宿主机挂载和共享密钥会穿透沙箱假设，需单独限制。把一次提权请求绑定明确命令、目标和期限，执行后记录真实结果。

## Context Engine 的四段工作

`ingest` 接收新用户消息、工具输出、文件变化和外部事件；`assemble` 根据当前任务装配系统/开发者约束、项目规则、任务状态、相关记忆和检索片段；`compact` 在预算紧张时保留目标、约束、已执行动作、失败尝试与下一步；`after-turn` 更新状态、保存 trace，必要时写入记忆或触发 Hook。不同来源的内容有不同可信度：网页和工具输出应作为数据，而不能变成更高优先级的指令。

子 Agent 只拿完成子任务必要的上下文。探索、实现、验证和总结阶段的装配重点也不同。压缩时应保留原始产物的引用，尤其不能把“猜测已完成”写成“工具已完成”。

## Hooks、Cron/Webhook、Background Task 不能互相替代

Hook 在生命周期点扩展行为，例如工具前安全检查、压缩前状态保存；Cron/Webhook 按时间或外部事件创建任务；Background Task 记录长时间构建、浏览器操作或远程子任务的状态。Hook 失败要明确是阻断、跳过还是降级；Webhook 要验签、去重并绑定正确会话；后台任务至少要有 queued、running、succeeded、failed、timed out、cancelled、lost 等可区分状态，并记录通知是否已送达。

后台任务账本不一定负责调度，调度器也不一定负责用户通知。自动化触发的动作仍受工具策略约束，不能因为来自定时任务就自动绕开审批。

通知也需要策略：有些长构建只在完成时通知，有些审批任务要在状态变化时通知，还有些低价值后台同步适合静默记录。客户端离线时可以排队，但回来后应合并重复进度，只呈现最新状态与关键失败。Cron 重复触发、Webhook 重送和后台任务完成事件都可能生成相同业务工作；用事件 ID 和业务幂等键去重，才能避免同一告警引发多个 Agent 同时修改一份资源。

## 中断、恢复与事件流

同一 session 通常应只有一个主 run 写入其状态；并行只读子任务可在受控范围内运行。运行时把 token、tool start/progress/result、permission request、task state、error 和 final 作为带顺序号的事件发给客户端。每个关键节点持久化消息摘要、计划、待审批请求、工具状态、工作目录与产物。重连后先补齐事件并核对状态，再继续。

用户中断时，尚未发起的动作可以停止；正在运行的工具可能只接收到取消信号；已经完成的外部写操作需要补偿而非“撤销模型回复”。发送消息、创建工单和提交 PR 等调用应使用稳定幂等键；状态未知时先向业务系统对账。审批请求要有唯一 ID、过期、取消与审计状态，恢复后重新核对身份、参数及目标资源。

## 用状态机做一次恢复演练

运行时可以把任务拆成 ready、deciding、validating、executing、observing、waiting_for_human、verifying 和终态。每次转移保存触发事件与状态版本：工具参数无效时从 validating 返回 deciding，连续失败超过阈值则进入失败终态；写操作执行超时且结果未知时进入待确认状态，不能直接再次执行；审批收到后从 waiting_for_human 恢复，先重查身份和目标资源。

演练可在每个阶段人为终止进程：模型未返回时只需重试推理；工具刚提交时必须对账；工具已成功但回复尚未到达客户端时应补发事件；任务取消后若外部动作已完成，应走补偿或人工处理。这样“断线恢复”不再是一句产品能力描述，而是一组能逐状态测试的行为。

## 面试会怎么问

影石创新面试涉及工具超时和恢复，要务科技面试问 Webhook 签名、幂等与补偿。回答“怎样保证长任务不断线”时，按事件持久化、状态机、幂等对账、权限恢复、客户端重连说明；回答“沙箱为什么不够”时，用 Docker socket 或允许的危险工具举例，展示执行环境和工具授权两个边界。
