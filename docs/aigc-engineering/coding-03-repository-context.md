# 编码 Agent 怎样读懂真实仓库

真实仓库不会把答案放在一个文件里。Agent 既要知道构建与测试怎么跑，也要判断需求涉及的模块、当前用户改动、依赖和代码风格。把整个仓库塞进上下文既昂贵又会淹没关键线索；更可靠的方式是像工程师一样逐层缩小范围。

## 从线索到代码位置

先读仓库入口说明和作用域内的项目规则，再用 `rg --files` 看目录、用 `rg` 找错误信息、接口名和相关测试。对候选文件只读需要的片段；遇到类型、引用链和继承关系再问 LSP。大型仓库可用符号索引缩小候选集，但索引可能滞后，实际文件和 Git diff 才是当前工作树事实。文件缓存可以避免重复读取，却必须以文件修改时间、内容哈希或版本标识失效，否则 Agent 会在旧代码上给建议。

| 能力 | 最擅长回答的问题 | 使用前要注意 |
| --- | --- | --- |
| `rg` | 某段文本、配置或调用在哪 | 结果是文本匹配，非语义证明 |
| LSP | 定义、引用、类型、诊断 | 语言服务可能没启动或索引滞后 |
| 代码索引 | 跨包符号、依赖关系 | 需确认索引版本 |
| 文件缓存 | 刚读过的片段是否要重读 | 写文件后必须失效 |
| Git diff | 用户当前做了什么改动 | 未跟踪文件也要检查 |

例如收到“登录失败时重试按钮无效”，先搜按钮文案和错误码，顺着事件处理函数定位 API 调用，再看测试与最近 diff。不要第一步就读完整个认证目录，也不要只看某个函数名就立即修改。

## 项目记忆文件能帮什么忙

`AGENTS.md`、`CLAUDE.md` 及团队约定通常写目录结构、构建命令、代码规范、常见坑、禁止动作和提交流程。它们帮助 Agent 少走探索弯路，也让不同会话遵循一致的协作规则。文件有作用域和可信度：位于子目录的规则可能只覆盖该包；说明可能过期；构建命令应和 package 配置、CI 或实际运行结果核对。项目规则不是对仓库内容的永久事实证明，更不能让不可信文件覆盖宿主的安全策略。

## 上下文压缩与恢复

长任务中的工具输出、日志、文件内容会占满模型窗口。压缩时不必保留每句聊天，却应保留：用户目标与约束、当前计划、已完成步骤、改动文件、关键代码位置、跑过的命令及真实结果、失败尝试、尚未解决的问题和下一步。尤其要区分“测试已通过”和“打算运行测试”。

恢复会话时，先加载摘要和项目规则，再检查工作目录、Git diff、未跟踪文件与测试状态。模型不能从旧摘要里的“准备修改 A”直接接着写，因为用户可能已经在暂停期间改了 A。摘要是继续探索的线索，工作树才是此刻的执行对象。

一个可用摘要最好写成可核查条目，而不只是一段流水账：当前目标是什么；完成了哪些步骤、对应哪些产物 ID；改动了哪些文件，是否还有用户原有 diff；哪些测试实际运行过、退出码如何；尝试过哪些失败路径；尚需哪一个权限或用户选择。恢复时逐项对照外部事实。若摘要说“测试通过”，但测试产物找不到，只能记为状态待核实，不能把它当确定结果。

选择性装配上下文可以按任务阶段变化：探索时多给目录与搜索结果；实现时多给目标文件、接口和约束；验证时多给 diff、测试失败片段；交付时给最终状态。大日志保留错误附近上下文与原始产物引用；重复搜索结果折叠；子 Agent 只回传相关发现和文件位置，不倾倒整段会话。

## 练习：控制一次检索预算

找一张真实的小 issue，限制模型只能先做两次搜索，再读取不超过五个候选文件。记录每次工具调用新增了什么信息。如果第三次请求仍与第一次相同，应改写查询条件或转向 LSP，而不是继续重复。完成后暂停会话，手动改动一个目标文件，再恢复，检查 Agent 能否发现这个新差异。

## 错误证据怎样进入上下文

假设测试报告显示 `TypeError`，堆栈把错误指向 `order_service`。这只是错误发生处，不一定是根因；Agent 需要再看调用方传入的数据结构、最近修改、测试 fixture 和类型定义。若 LSP 指向多个重载，也应读目标调用点，而不是把所有引用都塞给模型。最后在任务状态中区分“已核实：fixture 缺少字段”与“猜测：最近依赖升级改变了默认值”。压缩时继续保留这个区分，后续修复才不会建立在猜测上。

对图片、Notebook 和生成文件也要有专门处理。图片需要能看到实际内容，不能仅凭文件名猜；Notebook 的执行顺序可能不同于单元格顺序；生成文件应查上游定义和生成命令，而非直接修改生成产物。把这些文件都当普通纯文本搜索，常会让 Agent 找到表面位置却改错维护入口。

## 面试会怎么问

百度 MEG Agent 面试涉及 Claude Code 的压缩，字节 Agent 面试涉及滑动窗口与摘要，小红书与美团复盘也问到了上下文管理。若被问“Agent 怎么理解一个大仓库”，用搜索→关键片段→语义引用→diff→测试的顺序回答，并说明缓存和索引如何防过期；若问“压缩后怎么继续”，说清摘要保存什么、恢复后重新核验什么。不要把“模型记得上下文”当作恢复机制。
