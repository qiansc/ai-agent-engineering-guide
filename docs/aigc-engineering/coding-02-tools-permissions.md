# 编码 Agent 的工具与权限：把动作留在可控边界内

编码 Agent 最容易造成实际损失的环节，不是模型回答得不漂亮，而是一次工具调用真的改了文件、跑了命令或访问了远程系统。设计工具时要同时回答三件事：模型如何知道该调用什么，宿主如何判断能不能调用，执行结果怎样被读者和审计系统看懂。

## 一项工具需要完整合同

一项工具至少应有名称、描述、输入 schema、权限策略、执行逻辑、进度事件、结构化结果、错误类型和 UI 展示方式。比如 `edit_file` 不能只收一个自由文本 `input`。它至少需要目标路径、目标内容或补丁、期望的原文件版本；执行前应检查路径是否在授权工作区、文件是否在用户编辑后改变，执行后返回实际 diff。若发现版本冲突，应返回可区分的冲突错误，而不是覆盖文件。

| 工具 | 主要用途 | 易被忽略的风险 |
| --- | --- | --- |
| FileRead | 读源码、配置、日志、图片或 Notebook | 读入敏感内容、输出过长 |
| Edit / Write | 增量编辑或创建文件 | 目标错、覆盖用户改动 |
| Bash | 构建、测试、运行脚本 | 删除、联网、消耗资源或泄密 |
| Search / Grep / Glob | 定位文件与文本 | 搜索范围太大、噪声过多 |
| Git | 看状态和 diff，创建提交或 PR | 误提交、误切分支、覆盖历史 |
| LSP | 查定义、引用、类型和诊断 | 语言服务索引可能滞后 |
| Web / MCP | 读外部文档或服务 | 注入内容、凭证与外部副作用 |

通常先给搜索和受限文件读取较宽的权限，再将写文件、Shell 和外部服务按具体动作收紧。这里的“读”也不是无风险：配置文件可能含密钥，生产数据库查询可能读取敏感数据。

## 权限判断不是一个“自动 / 手动”开关

可以把运行模式分成只读规划、默认审批、低风险自动执行和受信任沙箱内的特殊模式；但每一轮真正生效的权限还来自系统默认、用户设置、项目约束、企业策略和临时授权。判断时先看不可覆盖的拒绝规则，再核对身份与资源范围，最后按工具和参数决定允许、拒绝或询问。

例如同样是 `bash`：`git status --short` 多半是只读检查，`curl ... | sh` 会联网并执行来源不明的脚本；`git push --force` 会改动远端历史。不能只按工具名分类，也不能只看命令字符串的开头。文件写入则要校验绝对路径、符号链接、工作目录范围、目标版本及当前 dirty state。执行后保留操作者、授权依据、时间、参数摘要、退出码和产物 ID，敏感参数要脱敏。

几种常见模式可这样理解：只读计划模式允许探索和生成方案，但不落地写入；默认模式让可接受的读操作直接进行，敏感动作询问；低风险自动模式只自动放行策略明确的动作；绕过审批模式只能在预先认定可信、可抛弃的沙箱及明确授权范围内使用。模式改变的是默认审批行为，不应覆盖企业 Deny 规则。策略来源有冲突时，要能向用户解释究竟是哪一条规则拒绝了动作。

用户确认应说明“将做什么、对哪个目标做、有什么副作用”。一次确认不能无限期授权其他文件或后来才出现的新命令。禁止或高风险动作如递归删除、硬重置、安装未知依赖、读取环境密钥，应有更严格策略；需要例外时由用户对明确目标重新授权。

## 远程执行里的权限桥接

远程 worker 发起工具调用，用户却在本地 IDE：执行端应创建唯一权限请求 ID，附工具名、参数摘要、目标、风险、有效期和 session ID。界面展示后返回允许、拒绝或取消；执行端核对响应仍对应同一调用，再继续。断线期间 pending 请求需要持久化，重连后能恢复展示；过期请求不可悄悄执行。即使本地不实现该工具，也需要能渲染远端工具的描述和结果。

如果用户批准后远程工具超时，要区分“执行失败”和“结果尚未确认”。对创建 PR、发消息等写操作，先用幂等键或业务查询确认是否已经成功，不能因为网络断开就换一个请求 ID 再执行一遍。

## 一个可测试的小练习

为 `read_file`、`edit_file` 和 `bash` 写三组策略测试：只读命令直接通过；仓库内文件编辑需要看 diff；仓库外路径、符号链接越界、疑似读取密钥和远程写操作进入拒绝或审批。再模拟用户在 Agent 读取之后修改了文件，验证 Agent 的编辑不会覆盖用户的新内容。

## 写入失败时怎么恢复

假设 Agent 打算把 `src/order.ts` 的一个条件分支改掉：读取后到写入前，用户又改了同一函数。工具应检查读取时的文件版本与当前版本，不匹配便返回 `CONFLICT` 和新 diff，要求 Agent 重新定位。若写入成功但 UI 连接断开，运行时应从文件内容与操作记录确认是否应用，不能盲目再写。若编辑只完成一半，需说明部分成功范围，必要时从保存的补丁和原始内容做人工可审查的恢复。

对于 Shell，退出码与标准错误要分开保留。构建超时可能是进程仍在运行，不应简单归类为构建失败；若用户点击取消，工具应尝试终止子进程并记录终止是否成功。大型命令输出可截断给模型，但完整日志应留在受控产物中供排查。命令输出若包含密钥，不能因为模型“需要分析错误”就原样回填上下文。

## 面试会怎么问

百度 Coding Agent 复盘提到密钥保护，小红书 Agent 复盘追问 Skill 误调用，字节 Agent 一面涉及工具与 Harness。回答“权限模型怎么设计”时，按主体—资源—动作—参数—执行环境—审计六项展开，并用一条写文件或 Bash 调用解释动态判断。回答“远程会话断线怎么办”时，补上 pending 审批的请求 ID、过期与恢复，避免只说“弹窗确认”。
