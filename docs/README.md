# 文章写作与索引

每个学习主题是一份独立 Markdown 文件，文件路径由 `index.json` 的 `articles[].path` 指定。网站服务只读取这些文章，不直接读取 `../../ref/`。

文章写法：

1. 用一级标题说明主题，开头直接讲清用途、前提和读者将学到的内容。
2. 主体按概念、机制、具体例子、操作步骤、失败与诊断组织；章节结构服从主题，不套固定模板。
3. 代码要能说明输入、输出与关键边界。示例数据不得冒充真实生产指标。
4. 需要图表时使用 Markdown 表格或 `mermaid` 代码块。图必须能帮助理解关系，保留文本解释，不硬编码颜色或主题。
5. 若主题在真实面经中被提及，紧挨来源之前设置 `## 面试会怎么问`，讲清原帖的问题、回答思路与追问边界；不要把教学推演冒充候选人现场回答。
6. 文章最后使用 `## 来源与延伸阅读`，列出可核验的外部 URL。正文不反复出现“某仓库说”。
7. 对有时效性的 API、协议和招聘规则写明版本或日期；社区面经保留个人样本的可信度边界。

服务在渲染时从 Markdown 的二、三级标题生成右侧目录，并按正文实时建立搜索索引。Mermaid 使用站内固定版本的离线资源，许可证保存在 `../assets/vendor/LICENSE-mermaid.txt`。修改 Markdown 后刷新页面即可看到新内容，不需要重新构建。
整理完一批文章后，从 `site/` 运行 `python3 check.py`，核对索引引用、30 天清单、章节、代码围栏与来源。文章完整性必须逐篇对照原始材料的小节、例子、练习和失败处理，不能靠字数阈值判定。
