# 从第一个工具调用到生产 Harness：11 级项目阶梯

学 Agent 最容易陷入两种循环：一直收藏项目，却没有一个能跑；或者第一个项目就上多 Agent、记忆和浏览器，出了错也不知道是哪层错。更稳的练习方式是每次只增加一类新能力，同时保留上一阶段的测试。下面的 11 级项目并非必须全部做一遍；如果你已有后端经验，可以从第 2 或第 3 级开始，但不要跳过“怎么验证”的问题。

每一级都用同一张交付卡记录：用户任务、最小输入输出、允许的工具、拒绝或人工接管条件、3 条成功样本、3 条失败样本、运行命令、成本与延迟。没有这些记录，一个 Demo 看起来会动，却很难在面试或真实交付中解释其可靠性。

## 第 1–3 级：把最小闭环和知识证据练熟

| 级别 | 做什么 | 新增能力 | 通过标准 |
| --- | --- | --- | --- |
| 1 计算器 Agent | 用户用自然语言提出算式，模型选择计算工具 | 结构化工具请求、参数校验、结果回填 | 模型不直接心算，除法为零明确报错，最多步数生效 |
| 2 网页研究助手 | 搜索公开页面，筛选证据并写简短结论 | 搜索、去重、引用与来源可信度 | 每个关键事实可点回页面；无证据时不补造 |
| 3 PDF 问答 | 对一组允许使用的 PDF 回答具体问题 | 解析、切分、检索、引用定位 | 答案指向页码/段落；扫描件失败与无答案有不同处理 |

第 1 级刻意简单。模型只负责选择 `calculate`，程序校验运算符、数字范围和步数，工具执行后将结果返回。故意让模型请求不存在的工具、填字符串参数或重复调用，检查宿主是否拦住。要理解的重点是：模型生成工具调用不等于工具已执行。

第 2 级引入外部不可信内容。搜索结果可能重复、过期或包含“请忽略前面指令”之类文本。先让搜索工具只返回标题、URL、摘要和抓取时间，再逐条读取少量候选页；结论中的关键句有可访问来源。评测时混入相互矛盾的页面，观察系统会不会强行调和。第 3 级则把网页换成文档：标题、表格、页码都可能在解析时损坏。检索的 `Hit@K` 与回答正确率分开测，不能因为答案流畅就当作 RAG 成功。

## 第 4–6 级：让 Agent 真正触碰软件和界面

第 4 级做代码审查 Agent，但只读仓库。输入一个 diff 和相关测试，输出按风险排序的评审意见：问题位置、可能后果、复现或验证方式。它可以建议加什么测试，不能凭空宣称“已运行测试”。准备几个人工确认过的历史 bug，测它能否指出真正危险的改动，同时统计无效告警。

第 5 级做浏览器 Agent，只在公开测试网站上练。一次任务可以是“打开商品列表，筛选条件，记录前三项标题和价格”，而非登录、付款或批量抓取。它需要先观察页面，再定位元素，执行动作后重新观察并确认状态变化。给它弹窗、延迟加载、空结果和选择器变化，验证能否停止、重试或请求人接管。截图和 DOM 都可能包含不可信文字，页面不能决定 Agent 的系统权限。

第 6 级做一个小型编码 Agent：读文件、搜代码、修改受限目录、跑目标测试、展示 diff。第一版不允许网络、密钥或自动推送。用一个可复现的小 bug 作为任务，记录它如何定位代码、提出修改、执行测试、处理失败。引入权限闸门：写文件前检查路径，执行命令前确认允许列表，提交前有人审。若模型改了无关文件，测试通过也不算成功。它比“让模型生成一段代码”多出的核心正是仓库上下文、执行边界和反馈循环。

## 第 7–8 级：从一次调用走向长期能力

第 7 级做消息入口与 Gateway。先支持一个测试频道，不必一口气接多平台：收到消息后分配会话 ID，按用户和任务路由，调用 Agent，持久保存状态，返回结果。再加入超时、重复消息、后台任务和心跳。用户在回复前重发同一请求时，系统应能识别任务 ID 与幂等键，不创建两个会产生副作用的任务。进程重启后能否恢复未完成任务，是这一关的核心测试。

第 8 级做可复用 Skill 包。选一类你已做过的任务，例如“审查 API 变更”或“研究资料并列出处”，把触发条件、步骤、脚本、模板、风险边界和验收标准写进能力包。最好让它有一个小的 smoke test：同一批任务，比较加载 Skill 前后的正确率、用时和工具误调用。若 Skill 太宽泛、经常在不适用场景触发，就要缩小触发描述或拆成两个。Skill 是流程知识，不是获取无限权限的通行证。

## 第 9–11 级：协作、个人助理与生产治理

第 9 级做一个研究写作流程：规划者列问题，检索者找来源，写作者整合，审查者检查引用。先用单 Agent 或确定性流水线做基线，再试多 Agent。两种方案都用同一任务集测事实正确、引用、成本和时延。若多 Agent 只是让角色互相转述，成本上升却没有质量收益，应退回简单方案。真正要练的是职责边界、交接格式、共享状态和停止条件。

第 10 级做个人助理的安全缩小版：只接一个消息入口、一个日历或笔记的模拟 API、按用户隔离的记忆。要求它能解释“我记住了什么、为什么记住、何时过期、如何删除”；定时任务要有显式授权与取消入口。不能因为是个人项目就忽略密钥与隐私。若想进一步研究 OpenClaw 或 Hermes 一类长运行系统，先对照自己的会话、权限和恢复设计，再看成熟项目如何解决这些问题。

第 11 级是生产 Harness，不是再增加一个聪明角色。准备固定任务集、运行环境版本、Runner、Trace、评分器和 CI 门槛。至少测任务结果、工具轨迹、安全违规、成本、延迟与中断恢复；对有副作用的动作做影子运行或人工批准。一个新 Prompt 或模型版本上线前，用同一批任务回放；不只看平均分，也看曾经失败的高风险样本是否复发。最终交付应能让别人按 README 在隔离环境中复现一条成功轨迹和一条失败轨迹。

## 怎么选择自己的下一关

如果目标是 AI 应用开发，先做到第 3 级，并把知识更新、权限过滤和用户反馈补进作品，再选一个第 5 或第 7 级的真实入口。如果目标是 Coding Agent / Infra，第 4、6、7、11 级更关键，尤其要展示文件并发、命令权限、Trace 和恢复。如果目标是 FDE，优先把第 2、3 级放进可见的用户流程，解释客户需求、试点指标和人工接管；不要用多 Agent 的数量代替交付效果。

每升一级，只加一项难能力，保留前一级回归集。把每次失败记录成“输入—期望—实际轨迹—根因—修复—回归样本”。这样到第 11 级时，你得到的不是十一个互不相干的玩具，而是一条看得见成长的工程作品线。

## 面试会怎么问

**问：你做过多个 Agent 项目，哪个最能证明工程能力？** 选一个有完整输入、失败、指标和恢复记录的项目。先说明用户问题，再画模型、工具、状态与权限边界；展示一次真实 bad case 和修复后的回归结果。项目数量不是重点。

**问：什么时候应该从单 Agent 升级到多 Agent？** 先有单 Agent 或确定性流程基线。只有专业分工、上下文隔离或可并行工作带来可测收益时才拆；还要计入交接、共享状态、冲突和成本。

**问：如何判断一个 Skill 真的有用？** 在固定任务集上做前后对照，观察成功率、误触发、工具调用和成本；失败时能定位是触发、步骤、脚本还是权限问题。
