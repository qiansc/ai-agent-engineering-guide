# Agent 工程面试 42 题：答案要点与追问训练

这套题按架构、工具、状态、RAG、评测、安全和项目七组组织。它不是公司题库，也不建议逐题背标准答案。每题给出回答时应覆盖的机制；能把机制连到自己的项目、指标与失败记录，才算真正掌握。自测时每题给自己 0–2 分：0 分无法解释，1 分能讲原理，2 分能拿出项目证据、取舍和边界。满分 84 分；低于 60 分时先补主项目证据包，而不是继续搜新题。

## 一、Agent 与架构（1–6）

1. **Agent、Workflow、Chatbot、Copilot 的边界？** 看谁决定下一步、是否调用工具改变环境、是否有持续任务状态。Chatbot 由用户逐轮驱动；Workflow 的主要路径预先定义；Copilot 辅助人完成任务；Agent 在设定边界内依据反馈选动作。真实产品可以组合这些形态。
2. **什么时候固定流程更好？** 输入规范、分支有限、可穷举、风险高且要强审计时，优先确定性流程。只把需要开放式判断的一小段交给模型，并说明省去 Agent 后会损失什么。
3. **ReAct、Plan-and-Execute、Reflection 各解决什么？** ReAct 交替判断与行动，适合边观察边走；Plan-and-Execute 先拆任务再执行，适合长任务依赖；Reflection 在输出或轨迹后检查缺陷。比较额外模型调用、计划过期和循环风险。
4. **Framework、orchestrator、runtime、sandbox、harness 如何分层？** Framework 提供编程抽象，orchestrator 负责调度，runtime 管任务状态和执行生命周期，sandbox 隔离代码与资源，执行 Harness 整合循环、工具、上下文、权限和观测。评测 Harness 另指任务集、环境、runner 与评分系统，答题时先说明语境。
5. **如何防死循环与路径震荡？** 设置步数、时间、成本上限；记录动作指纹与状态是否进展；相同动作反复失败时停止、换策略或转人工。终止条件既看模型输出，也看程序可验证的目标状态。
6. **如何把模糊需求变成可评测任务？** 定义使用者、输入、期望产物、自动化权限、不可接受失败和样本分层。先拿一个窄场景验证，再扩范围。

## 二、工具、协议与权限（7–14）

7. **Function Calling、Tool Use、MCP 有何区别？** Function Calling 常指模型生成符合工具 schema 的调用意图；Tool Use 包含选择、执行、结果回传和错误处理；MCP 是客户端与工具/资源服务之间的标准化接入协议。三者不能互相替代业务授权。
8. **MCP host、client、server 各做什么？** Host 管用户体验、权限和多连接；client 与某 server 建立协议连接；server 暴露工具、资源或提示。回答应落到谁持有凭据、谁决定能否执行。
9. **stdio 与无状态 HTTP 如何取舍？** 本地进程、桌面集成可用 stdio；远程服务更需要 HTTP、认证、伸缩与网络治理。协议版本变化快，需按当前规范确认初始化、会话与 transport 语义，不能把旧版 session 规则当新规范主路径。
10. **schema 怎样减少工具参数错误？** 精确命名、枚举、必填、范围和示例；执行前仍做解析、业务约束、权限与对象存在性检查。错误返回应结构化，避免模型反复猜。
11. **超时、限流、部分成功怎样处理？** 区分可安全重试的读操作和有副作用的写操作；采用退避、总预算和熔断。写操作超时先查结果，按幂等键决定重试或补偿。
12. **副作用工具怎样做幂等、确认与补偿？** 用稳定任务/操作 ID、服务端唯一约束与执行记录；高风险动作展示对象和影响后由人确认；补偿是新的业务动作，不假装数据库回滚能撤销外部世界。
13. **如何阻断工具输出中的 Prompt Injection？** 外部网页、文档和工具返回只作为数据；系统权限由宿主策略判断。限制工具能力、隔离来源、校验输出、审计异常调用，而不只靠一句“忽略恶意指令”。
14. **工具太多时如何发现和路由？MCP 与 A2A 分别在哪层？** 先按任务与权限筛选候选工具，延迟加载描述，避免全部占满上下文。MCP 侧重工具/资源接入，A2A 侧重 Agent 间发现、任务与协作；两者可并存。

## 三、状态、Context 与 Memory（15–20）

15. **消息历史、运行状态、context、长期 memory 的区别？** 消息历史是对话记录；运行状态是任务进度和副作用记录；context 是本次模型实际可见内容；memory 是经筛选、跨任务可复用的信息。存储位置和保留期限不同。
16. **长任务怎样暂停、恢复、取消、重放？** 状态机与 checkpoint 外置；每步记录版本、完成结果和待执行动作。恢复时先核对副作用，重放应在安全环境与固定依赖下进行；取消不保证撤销已完成操作。
17. **压缩保留什么，怎样测？** 保留目标、约束、用户偏好、已完成/未完成步骤、关键证据与外部对象 ID；裁掉冗余对话和可重新获取的工具原文。用长任务回归集比较压缩前后任务成功率与遗漏事实。
18. **长期记忆何时写入和遗忘？** 只写未来有用、得到授权且可标明来源与有效期的信息；去重、纠错、过期删除并支持用户撤销。不要把每次模型猜测写成事实。
19. **怎样隔离用户、租户和任务？** 身份由入口绑定，检索与工具按服务端权限过滤；缓存键和 memory 命名空间包含授权边界；审计跨租户访问。模型不能自行指定 tenant ID。
20. **多个 Agent 同时写共享状态怎么办？** 拆独立产物、单写者汇总，或用乐观版本检查、锁与冲突合并规则。并行前先画依赖图，不能把文件覆盖交给自然语言协商。

## 四、RAG（21–27）

21. **文件上传到回答的全链路？** 上传与病毒/格式校验、解析、切分、元数据与 ACL、Embedding/索引、查询改写、检索、rerank、生成、引用和日志。每段能单独测。
22. **PDF、表格、代码和网页如何切分？** 尊重结构边界：PDF 看版面与标题，表格保留行列语义，代码按符号和依赖，网页去导航噪声。chunk 大小由问答粒度和召回实验决定。
23. **BM25、dense、hybrid、rerank 如何组合？** BM25 擅长精确词项，dense 补语义表达；混合检索扩大候选，再 rerank 精排。增加阶段会增加时延，应在固定集上验证收益。
24. **异构分数怎么融合？** 不同检索器分数不可直接相加，可做校准、归一化或使用基于排名的融合；按查询类型检查是否偏向某一来源。

    一个小例子：只列候选 A、B，其余候选略。BM25 给 A 12 分（第 1）、B 8 分（第 2）；dense 给 A 0.20 分（第 5）、B 0.86 分（第 2）。原始分数相加后 A 为 12.20、B 为 8.86，几乎由 BM25 的数值尺度决定，而不是两路证据的平衡。若用 RRF，取 `k=60`，按 `1/(k+排名)` 汇总，A 为 `1/61+1/65≈0.03178`，B 为 `1/62+1/62≈0.03226`，B 因两路排名都靠前而胜出。RRF 不需要直接比较原始分数；若选归一化融合，则应在固定标注集上校准两路分数与权重，并检查不同查询类型的效果。
25. **召回差、答案错、响应慢怎样定位？** 先查解析和索引，再看 Recall@K、排序、证据进入上下文与生成依据性；时延按检索、rerank、模型和工具拆开。
26. **更新、删除、权限如何传播？** 文档和索引版本化，更新事件可追踪；删除和权限撤销要使检索、缓存与历史引用失效或受控。设计“旧版本不得再返回”的回归用例。
27. **Recall@K、MRR、NDCG、groundedness 各测什么？** 前者看相关证据能否进入前 K；MRR 看首个相关结果位置；NDCG 看分级相关性排序；groundedness 看答案是否受给定证据支持。它们不等于最终业务成功率。

## 五、评测、观测与性能（28–34）

28. **Agent eval 比普通文本 eval 多什么？** 还要测动作轨迹、工具参数、状态变化、副作用和安全边界。最终答案正确但过程越权，仍是不合格。
29. **Outcome、trajectory、tool、safety 怎么评分？** 分别看完成结果、路径效率与重复、调用选择与参数、越权或风险。定义任务级权重与不可妥协门槛。
30. **LLM-as-Judge 怎么校准？** 写 rubric 与正反例，和人工标注集比较一致性；注意位置、长度和同模型偏好。确定性规则可判的事项不交给 judge。
31. **最小 trace 包含什么？** run/task/step ID、时间、版本、输入摘要、工具调用与结果引用、状态迁移、token、费用、时延、终止原因和人工动作；敏感内容脱敏。
32. **五分钟任务变二十分钟？** 先分队列、模型、检索、工具与重试耗时，再看 token、动作数和下游 P95；固定输入回放，避免凭印象换模型。
33. **如何控制成本？** 给 run、模型、工具和租户设预算；减少无效反思和重复检索，按任务路由模型；同时监控质量和人工接管，不能只削 token。
34. **线上 Bad case 如何回流？** 去敏并冻结输入、环境、版本和期望结果，加入分层回归集；修复前先复现，灰度后看总体和分群退化。

## 六、安全与生产（35–39）

35. **如何防注入、SSRF、越权和危险调用？** 标记不可信来源，宿主校验权限；网络限制协议、IP、重定向和大小；写工具最小权限、审批与审计。防线要覆盖输入、决策和执行。
36. **哪些操作要 HITL？** 高金额、对外发送、不可逆删除、权限提升及法律安全风险。审批页展示对象、影响和可回退性，避免无意义“同意”按钮。
37. **Sandbox 限制什么？** 文件系统、网络、进程、凭据、CPU/内存/时间与可调用工具；按任务最小授权并清理环境。
38. **如何灰度、回滚和熔断？** 先离线、shadow、canary，再逐步放量；版本化模型、Prompt、工具 schema、索引和策略。安全指标越线时停止新任务并保留恢复路径。
39. **如何审计一次决策？** 保存用户身份、授权、状态版本、模型和工具版本、动作与结果引用、人工确认及时间线；日志既可追溯又要保护敏感数据。

## 七、项目与通用工程（40–42）

40. **最难故障是什么？** 按症状、影响、trace、假设、根因、修复、回归结果讲。没有真实事故就明说，并展示设计过的故障注入实验。
41. **去掉 Agent 项目还能做吗？** 先指出固定软件可承担的部分，再界定确实需要根据开放反馈选动作的环节；若替代方案更可靠，应愿意简化。
42. **项目改善了什么？** 报指标定义、基线、样本量、评测条件、改动后结果和代价；对未知收益与试点限制如实说明。

## 八组关键题的完整答法

### 1–2：为什么需要 Agent，何时退回 Workflow

先描述任务是否有开放式不确定性。例如“按审批表单的固定字段创建工单”路径明确，固定 Workflow 更容易测试与审计；“从多份资料与用户回复中判断下一步应补什么信息”可能需要受限 Agent。再划分职责：程序负责身份、权限、预算、状态和最终提交，模型在允许的工具集合内选下一步。若面试官问“直接让模型自动处理所有分支会怎样”，应回答模型可能在新输入下走出未预料路径，副作用、成本和终止难以保证。误区是把“用了 LLM”当 Agent 定义，或把所有步骤都交给模型；正确判断单位是哪个阶段需要动态决策，以及这个动态性带来多少收益。

### 4–5：Harness、Runtime 与死循环

执行 Harness 组织模型、工具、上下文、权限、循环控制和观测；runtime 使任务可持续运行，处理状态、调度、暂停与恢复；sandbox 限制执行环境；评测 Harness 是数据集、隔离环境、runner、grader 和报告。名称在不同项目里可能有重叠，回答时先给职责，再映射到具体实现。追问“Agent 一直在同两条路径之间切换怎么办”：记录规范化动作与状态指纹，若重复调用未带来状态进展，触发停止、改策略或人工接管；同时设步数、时间和费用上限。误区是只在 Prompt 写“不要循环”，或只设最大步数却不分析工具错误是否诱发重复。

### 11–12：超时、重试与副作用

以创建订单工具为例，客户端超时不能证明订单未创建。宿主在首次调用前生成稳定操作 ID，工具服务持久化该 ID 与结果，重复请求返回原结果。超时后先按 ID 查询；确认未执行且仍符合业务条件时才重试。若供应商没有幂等能力，需本地记录、查询接口和人工核查，不能自动盲重试。高金额或不可撤销动作在提交前显示对象、金额、影响并请求批准；提交后若业务允许撤销，补偿也是一个受审计的新动作。追问“幂等与去重有什么区别”：去重常识别重复输入，幂等强调同一业务操作多次请求产生同样效果；仅靠模型每次生成同一个参数不可靠。

### 16–18：状态、压缩与长期记忆

长任务应有明确状态机与 checkpoint，记录完成步骤、外部对象 ID、待审批动作和版本。恢复时先验证上次副作用是否已发生，再继续未完成步骤。Context 压缩解决的是模型窗口，不应删除真实任务状态；保留目标、约束、决定、未完成事项和关键证据，原始大工具结果可留在受控存储并按需取回。长期记忆只写跨任务确有用、获得授权、有来源和有效期的事实。追问“压缩摘要说用户允许退款，但当前用户刚撤回授权”：以当前权限和结构化业务状态为准，摘要不能提升权限。误区是把聊天历史、任务状态和记忆都存在同一段自然语言里。

### 25–27：RAG 错答的分层定位

先准备有标准证据的样本。原文不存在或解析失败属于摄取问题；索引中存在但 Recall@K 低属于检索问题；相关文档在候选中却排不前属于排序问题；正确证据已进入 Context 但答案无依据属于生成问题。文档更新与 ACL 变化还可能造成索引或缓存版本错误。Recall@K 看证据是否进前 K，MRR/NDCG 看位置与分级相关性，groundedness 看输出是否受证据支持，任务正确率看用户目标是否达成。追问“增大 K 是否一定改善”：可能带来噪声、成本和权限风险，应先看失败分布，再做同集对照。误区是用一个“RAG 准确率”概括所有层。

### 28–30：Agent Eval 与模型裁判

普通文本评测多关注输出内容，Agent 还必须看过程中的工具选择、参数、状态变化和副作用。建立四层评分：Outcome 是最终任务，Trajectory 是路径与重复，Tool 是调用正确性，Safety 是越权、危险操作和误放。确定性检查如 JSON 合法、金额上限、测试退出码应由程序判；语义质量可由人工或 LLM-as-Judge 按 rubric 评价。若使用模型裁判，先用人工标注样本校准，检查长度偏好、顺序偏好和同模型偏好；记录裁判版本。追问“最终结果正确但先读取了无权文档算成功吗”：不能算，安全门槛应独立于 outcome。

### 35–39：安全、人工确认与发布

网页、邮件、检索片段和工具结果都是不可信数据。模型可以据此回答，但不能获得新权限；执行层重新检查用户、任务、资源与动作。网络工具限制协议、目标 IP、重定向和响应大小，sandbox 限制文件、网络、进程、凭据和资源。高风险动作在人能判断的地方暂停，审批界面展示具体对象与影响。发布先离线回归，再 shadow、canary 和逐步放量，记录模型、Prompt、工具 schema、索引与权限策略版本；触发安全或质量门槛时停新任务并回滚。追问“回滚模型就够了吗”：不够，已执行的外部副作用无法靠模型回滚，状态与工具版本也必须兼容。误区是把安全等同于一个审核 Prompt。

### 40–42：项目证据的完整结构

先用一句话讲用户问题和任务范围，再说为什么用受限 Agent、自己负责哪部分、基线是什么。一个失败案例按现象、影响、trace、根因、修复和回归结果讲；若根因未证实，列出已排除假设和下一项实验，不编造结论。结果指标附分母、样本来源、时间窗口和代价，线上采用与离线分数分开。追问“如果去掉 Agent”：指出固定流程可接管哪些部分，剩下的动态决策是否值得保留；若不值得，愿意简化。误区是用“用了 LangChain/MCP/多 Agent”替代个人贡献，或把团队收益全部写在自己名下。

## 三道综合题的作答演练

**题一：设计会调用外部工具的客服 Agent。** 先限定只读问答或允许创建工单，列出用户身份、知识库 ACL、工具 schema 和审批边界。状态记录每次调用，副作用工具按操作 ID 幂等。离线集覆盖正常、缺资料、过期资料、越权与工具超时；线上看成功率、人工接管率、误放率和 P95。追问“工具超时但工单已创建”时，回答先用操作 ID 查询外部结果，再决定重试或人工处理。

**题二：长对话压缩后 Agent 忘记客户禁用外发邮件。** 暂停外发工具，查压缩前后事实、权限策略和 trace；将禁令固定在宿主策略，关键任务约束进入结构化状态，压缩只处理模型可见上下文。补长任务回归集，验证压缩前后都不能越权。单纯扩大窗口不能解决安全边界。

**题三：RAG 改成 hybrid 后离线分数升了，线上投诉更多。** 检查离线集与线上查询类型、索引和权限版本是否一致；按租户、文档类型和新旧文档分群。分别看 Recall@K、排序、引用与最终正确性，还要看 P95 与成本。可能是召回扩大引入噪声，也可能是更新链路问题；先用日志和样本区分，再决定回滚或调整融合。

## 按岗位裁剪 42 题

应用 Agent 岗先把 1–6、10–13、15–18、21–27、28–34、40–42 练到能联系项目，再补协议细节。Coding Agent 岗加重 4–5、13–20、31–39，并能解释文件权限、沙箱和并发写入。平台岗需要把 9、11–12、16、19–20、31–39 讲到容量、租户隔离与发布恢复。FDE 岗应在这些技术题之外，准备需求澄清、试点范围、客户数据、采用率和安全叫停。模型/算法岗不能只练这 42 题，还要补 Transformer、微调、推理和实验设计。

题库不是进度条。抽十题随机口述，每题两分钟，要求至少出现一个具体组件、一个失败边界和一个可验证指标；答不上来就标记缺哪种证据。隔一周换业务场景再答一次，检查是否真正掌握方法，还是只记住固定例子。若项目材料无法支撑第二遍追问，应优先回到代码和数据，而不是扩展到第 43 题。

## 一次自测怎样判分

以第 12 题“副作用工具如何幂等”为例：只说“加一个唯一 ID”得 1 分，因为还没说明 ID 由谁生成、在哪里校验、超时后怎样确认；若能讲出宿主生成稳定操作 ID、服务端唯一约束与结果记录、重复调用返回原结果、未知状态先查询、无法撤销时用补偿，并用自己项目的失败样本或测试验证，可得 2 分。若把幂等完全交给模型提示，则应给 0 分。

第 25 题也类似：只说“调 chunk 和换模型”得分很低；能先检查解析、权限、Recall@K、排序、证据进入 Context 与生成依据，再给固定样本实验，才算完整。评分不是为了比较候选人，而是让自己发现“会背概念”和“能解释系统行为”之间的距离。

题目顺序可以按岗位调整，但不要跳过项目与通用工程三题。它们能检验前面所有概念是否真的在你的系统里发生过。

## 面试会怎么问

真实面试通常不会照着 42 题从头问到尾，而是从一个项目连续下钻。例如先问“为什么选 Agent”，再追“调用错工具怎么办”“长任务中断如何恢复”“怎样评测改进”。练习时从题库中挑一条链，限定自己用同一个项目回答；每一步都说出实现位置、失败样本和验证办法，不要为每道题编一个互不相干的理想系统。

另一类问法会突然从 Agent 切到后端或算法。若前一题是“副作用工具超时”，下一题可能是数据库唯一约束或消息重复投递；若前一题是“上下文隔离”，下一题可能是缓存 key 与多租户。回答要把新问题接回真实执行链，而不是继续背 Agent 术语。
