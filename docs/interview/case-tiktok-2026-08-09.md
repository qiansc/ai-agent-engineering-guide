# 一场从会议转写问到 Agent 架构的面试

这场 2026 年 8 月 9 日的 AI Agent 开发一面很适合练“沿着项目一路深挖”。候选人从会议转写项目讲起，面试官没有停在“用了哪个模型”，而是沿着音视频链路、ASR 选型与评测、隐私和架构，接着问 RAG、Token、Transformer、长上下文、训练方法与多 Agent，最后落到两道树题。下面保留这个推进顺序，并把每一组问题变成可练习的回答。公司的名称与题目均来自候选人自述，不代表招聘方的官方题库。

## 先把项目讲成一条可检查的链路

开场的两个问题是“为什么选 AI Agent 方向”和“会议转写从音视频输入到文本生成经历什么”。可以用一句话定位项目：它解决谁在什么场景下的哪种麻烦，自己负责哪段链路，如何判断做得好不好。随后按数据实际流动说，而不是从模型名开始说。

一个完整的会议转写链路通常包含：客户端采集与上传，鉴权和会话标识，音轨提取、重采样或降噪，语音活动检测与分段，ASR 推理，标点与时间戳恢复，说话人分离，专有名词纠错，片段合并与人工修订，最后才可能进入摘要、检索或行动项提取。不是每个项目都做了这些步骤。面试时要区分“我负责的”“系统已有的”和“我会怎样改进”，不要把通用架构说成自己的成果。

如果做实时转写，再交代流式与批处理差异：分段过短会丢上下文，过长会增加首字延迟；网络断线要按会话和分片序号续传；部分结果与最终结果可能不同，界面需要支持修正。若后续要生成会议纪要，还需保存原始片段与时间戳，让摘要中的事实能回到音频位置核对。

## ASR 选型不是报一个供应商名字

“为什么选阿里云 ASR？对比过别家吗？”这题的关键是决策依据。先给业务约束：语言或方言、多人重叠说话、实时延迟、敏感数据处理、并发量、预算、可用区域。然后说明对比样本来自哪里，是否覆盖噪声、专业术语、不同口音、长短会议，而非仅用一段清晰语音试听。

评测至少拆成三层。字词层可看 CER/WER，必要时单独统计人名、产品名和数字；片段层看时间戳、说话人分离及漏识别；业务层看纪要与行动项是否因转写错误而改变。对中文，CER 往往比英文式的 WER 更容易定义，但标点、数字归一化与同音词要预先统一标注规则。不要只报一个“准确率 95%”：说明测试集规模、场景组成、基线与置信区间，才能让数字有意义。

错字可以通过术语表、热词、后处理词典或人工修订缓解；漏字先检查静音检测、分段边界与音质。若只在 LLM 后处理中“润色”，模型可能把没听到的话补成貌似合理的内容。更稳妥的办法是保留原始 ASR 文本和音频定位，把低置信度片段交给复核，而不是让生成结果覆盖证据。

## 隐私和系统架构要一起回答

面试官接着问视频通话隐私，以及系统采用中心化还是去中心化。这两题不能只用“加密”和“看情况”作答。先梳理数据：原始音视频、转写文本、摘要、说话人标识与日志分别由谁访问、保存多久、是否可用于训练、何时删除。传输加密、静态加密、最小权限和租户隔离是基础；更关键的是第三方 ASR 服务的数据处理边界、用户告知与同意、访问审计、删除传播、故障时是否把原始内容落入普通日志。若是未成年或跨境数据，还需按实际业务合规要求处理，不能在不清楚所在地规则时随口承诺“合规”。

架构选择可以给出一条具体答案：由服务端统一管理会话、鉴权、任务状态、调用配额和审计，采集与展示在客户端，ASR 推理服务可以独立伸缩。这是“控制面集中、处理面可拆分”，不等于所有数据都必须经过一个单点。若要在端侧处理敏感音频，需解释设备算力、模型大小、更新和降级。若有人主张完全去中心化协作，追问其如何保证统一权限、数据删除、计费和故障追踪。面试中应讲清所选设计的约束，而不是给架构贴标签。

## RAG：把“怎么切”变成实验题

这一组追问连续涉及 Chunk 策略、大小以及切分差异。先说被检索的到底是什么：是会议逐字稿、纪要，还是企业知识库？逐字稿按固定字符切，会把一个发言拆断；只按会议整体切，又可能太长且主题混杂。较可行的起点是“会议 → 议题/时间段 → 说话轮次”，保留时间戳、说话人、会话 ID、权限与前后文关联。检索命中一个片段后，再按相邻片段补足上下文。

Chunk 大小没有通用最优数。做一个小规模标注集：问题、应命中的片段、最终答案及引用位置。对几种大小、重叠率与语义切分策略同时测 Recall@K、噪声比例、最终答案依据性、延迟和成本。要特别关注跨边界问题与多说话人争论：较小片段精确但可能断章取义，较大片段完整却更容易稀释匹配。面试官要听的是实验设计和误差分析，不是背“512 token + 10% overlap”。

## 从 Token 一直追问到 Transformer

“为什么一个单词会拆成多个 Token？”可以用词表和子词切分解释：模型输入不是字符或单词本身，而是词表中的离散 ID；常见片段可能对应一个 Token，罕见词、复合词或不同语言文字可能被拆成多个片段。实际拆法取决于 tokenizer，不能凭可见字符数估算。用字符会让常见词很长、序列变长；只用完整单词则词表巨大且难处理生词。子词是覆盖率、词表大小与序列长度的折中。

Q、K、V 追问可以从“当前位置要看谁”开始：每个位置的表示投影成 Query、Key、Value；Query 与各 Key 的相似度经缩放、掩码和 softmax 得到权重；加权汇总 Value，生成当前位置新的表示。多头注意力让不同投影空间学习不同关系，但“某一头专门负责某语法”并非总能机械解释。完整 Transformer 还包括位置编码或位置信息、前馈网络、残差与归一化。回答时在纸上写出一行公式，再说明 causal mask 为什么阻止自回归模型看见未来 Token，比只背三个英文词更稳。

## 长上下文：容量不等于有效使用

这场面试围绕 Context 连问七题：什么是上下文、窗口为何不同、能否调整、是否越大越好、怎样训练长上下文，以及 Lost in the Middle。回答时先区分“模型一次可处理的最大 Token 数”和“在这个长度上仍能可靠提取、推理的能力”。窗口受训练时的位置编码、长序列数据、注意力实现、显存与服务成本等共同限制；接口能否调整最大输入还受具体模型与服务参数约束。某个产品的具体窗口数会随着版本变化，应在面试当天核查官方规格，别凭旧记忆回答一个固定数字。

Lost in the Middle 指长上下文中的信息位置影响检索与利用：中部的重要内容可能比首尾更难被用到。实践中可先检索相关片段，把任务目标、约束、最新状态与关键证据放到清晰结构里，减少无关对话；必要时做分层摘要或外部状态存储。不要把“加大窗口”当成解决一切的办法：成本和延迟会上升，噪声也可能增加，长任务仍需检查摘要是否遗漏约束。

如果追问“怎么让模型支持更长上下文”，可描述继续训练或专门的长上下文训练、位置机制与推理优化，以及用不同长度和位置分布的任务评测有效长度。但不要把推理时某种位置缩放方法说成“任何模型无需训练即可无损扩窗”。真正的证据是长度分桶测试和真实任务表现，而不是配置文件中的最大数值。

## 训练方法与多 Agent：知道边界更重要

SFT、PPO、DPO、GRPO 被问在同一题里。可以按“用什么反馈、优化什么”解释：SFT 学示范答案；PPO 属于策略优化，常配合奖励模型与约束；DPO 用偏好成对数据直接优化偏好目标；GRPO 是一类基于组内相对反馈的策略优化方法。它们不是同一个问题的四种万能替代品，训练成本、数据要求和稳定性不同。若自己没做过某个方法，要明确说理解原理但没有实践经验，再讲能核实的部分。

多 Agent 题紧接着问“为什么不是单 Agent”和“为什么需要中心化编排”。先从任务依赖来判断：可并行且边界清楚的搜索、审阅或多方案生成可以拆角色；若多个 Agent 只是互相转述同一上下文，会增加延迟、成本和冲突。中心编排者可以维护任务状态、预算、权限和最终验收，子 Agent 只拿所需上下文与工具权限。但“中心化编排”不要求只有一个进程，也不意味着所有推理必须串行。追问时说明并行任务如何汇合、冲突如何裁决、失败如何恢复，才算回答架构。

## 两道算法题怎么练

第一题把扁平 List 转成树形 JSON。先确认节点字段、父 ID 是否可能缺失、是否允许多个根、重复 ID 和环怎么处理。线性做法是第一遍按 ID 建映射与空 children，第二遍按 parent ID 挂接；根节点收集到数组。若输入有环或一个节点挂到自己的后代，简单挂接会形成非树结构，需要额外检测。排序要求也应先问清。时间复杂度通常是 O(n)，但节点对象与映射也占 O(n) 空间。

第二题之字形层序遍历。用队列做 BFS，每一层先记录当前队列长度，把该层节点依次取出。可以把值写入长度为该层节点数的数组：正向层放下标 `i`，反向层放下标 `len-1-i`；子节点仍按左、右正常入队。这样不会因为倒序取节点而打乱下一层访问次序。总时间 O(n)，额外空间取决于最宽的一层。练习时手算三层不对称树，特别检查只有右孩子和空树。

## 面试会怎么问

把这场面经当作一次连续模拟，而不是二十三道孤立问答。先限时两分钟讲项目链路，让同伴沿“为何这样选 → 怎样评测 → 出错怎么办 → 数据能否安全处理”追问；再限时五分钟从 RAG 切分讲到一次可复现的对比实验；最后不看笔记解释 Token、Attention 与上下文窗口的边界。每答一个技术名词，都补一句“在我的项目里它位于哪一步，我有什么数据能证明选择有效”。

如果项目没涉及会议转写，也可把这套顺序迁移到自己的 RAG 或 Coding Agent：输入链路、服务选型、质量评测、安全边界、基础原理、架构取舍和手写代码。不要借用别人的项目经历；面试官往往会沿个人贡献和具体数据继续追问。
