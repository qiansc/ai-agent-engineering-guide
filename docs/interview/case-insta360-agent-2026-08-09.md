# 影石创新 AI Agent 一面：从 Harness 到 Java、MySQL 的逐题讲解

这场一面由候选人回忆，发生在 2026 年 8 月 9 日，原帖列出 20 道具体问题和反问环节。候选人表示后来没有通过，前半场谈 Agent 工程，后半场切到 Java、数据库和一道数组题。下面按题目出现顺序讲可用的回答思路；涉及项目经历的题目必须换成你自己的事实，不能把示例当成候选人的现场回答。

## 开场与编码工作方式：第 1～4 题

### 1. 怎样介绍经历与选择 Agent 的原因

用一条与你最相关的项目线索开场：业务问题、你负责的环节、怎样验证结果。选择 Agent 方向的理由最好来自任务特征，例如步骤难以完全预编排、需要根据工具观察决定下一步；如果任务只有固定几步，说明你会优先使用 Workflow。不要靠“行业前景好”代替技术判断。没有 Agent 项目经历，也可以诚实介绍做过的 RAG、自动化或后端系统，再讲希望补齐的运行时能力。

### 2. AI Coding 工具如何融入日常开发

题目提到 Claude Code 一类工具，重点不是背工具排行榜，而是讲工作方法。可以分成探索、方案、实现、验证四段：让工具定位调用链和既有实现；复杂改动先审计划和文件边界；小步编辑、查看 diff；最后跑相关测试、类型检查与人工审查。敏感仓库要遵守权限和数据规则。若你没用过某工具，就谈自己实际用过的工具及限制，别声称它帮你“自动完成”了未验证工作。

### 3. Spec Coding 与 Harness 分别承担什么

Spec Coding 强调先把目标、约束、接口、验收与非目标写清，再进入实现。Harness 是承载执行的程序环境：给模型装配上下文、提供工具、拦截未授权动作、保存状态、处理错误、运行验证并决定何时结束。Spec 告诉系统要交付什么，Harness 保证执行过程能被控制和检查。复杂任务之所以更稳，并非模型突然更聪明，而是失败可观察、步骤可恢复、产物可验收。

给一个具体例子：需求是“为订单列表增加筛选项”。Spec 写明筛选字段、默认值、空结果、权限和测试；Harness 让 Agent 查现有接口、编辑目标文件、运行测试、展示 diff。若测试失败，它把错误作为新观察送回；若模型请求删除无关文件，它阻断工具调用。

### 4. 从零搭一个 Agent 有哪些模块

先问清任务目标与成功标准，再画最小链路：用户入口和 session → 上下文装配 → 模型决策循环 → 工具注册与校验 → 执行结果回填 → 终止验收。旁路补状态持久化、权限、预算、trace 与人工接管。用一个只读工具先跑通完整循环，比一上来接几十个工具更容易查错。若要做生产版，还需处理超时、重试幂等、敏感信息、评测集和部署监控。

## 工具故障、记忆和上下文：第 5～8 题

### 5. 外部工具超时或异常怎么处理

把错误分成参数错误、权限拒绝、资源不存在、限流、暂时性网络失败和结果不确定。只读调用可在有预算时按退避策略重试；写操作超时先用幂等键或业务查询确认是否已经成功，不能盲目重复。运行时记录工具名、参数摘要、错误码、耗时与产物 ID，交给模型清楚的观察。连续失败时切换备用来源、暂停或人工接管，最终回答说明尚未完成什么。

### 6. 让模型参与错误分析有什么利弊

模型适合读堆栈、日志和工具错误，提出下一步排查假设。例如 `PERMISSION_DENIED` 是权限问题，不该让它换个工具绕过；测试失败则可以定位相关代码与 fixture。模型的建议必须通过确定性校验和权限策略，尤其不能让它自主重试付款、发消息或删除文件。收益是对复杂错误有弹性；代价是额外调用成本、错误归因与无限循环风险。给恢复尝试设置次数和成功检查。

### 7. 短期、长期记忆怎样实现

短期记忆服务当前任务：最近消息、工具观察、计划与待办，通常存在会话状态中，并按 token 预算筛选。长期记忆是跨任务复用的稳定信息，如用户明确同意保存的偏好或已验证的项目约定；它需要写入条件、作用域、更新时间、权限与删除机制。两者都不能把模型猜测直接存成事实。底层可选关系库保存结构化状态、对象存储保存产物、检索索引查相关片段；向量库只是检索方式之一，不等于全部记忆。

### 8. 为什么压缩上下文，怎样防止信息丢失

长任务的日志、文件和对话会占满窗口，成本和噪声同时上升。压缩时保留用户目标、约束、已执行副作用、修改文件、测试结果、失败尝试、待办和来源引用；大段原始输出可存外部产物并留指针。恢复后重新检查 Git diff 与工具状态，特别要把“已执行”与“计划执行”分开。压缩质量可通过暂停—恢复题集评估：恢复后是否重复发消息、覆盖用户改动或忘记关键限制。

## 提示词、幻觉、成本和 Skill：第 9～12 题

### 9. 除了堆规则，提示词还能怎么优化

先改输入结构：清楚说明任务、角色、可用工具、输出格式和成功条件；给少量贴近目标的示例；把不可靠资料标成引用数据；必要时用分步计划和结构化输出。遇到失败先看是哪一层：检索资料不相关、工具 schema 含糊、模型漏掉约束，还是验收标准太松。只增加“请仔细”通常无法修复执行器问题。修改提示词后要用固定样本与新样本一起测，防止只对已知题过拟合。

### 10. 模型幻觉怎样处理

先按类型诊断：缺事实时用检索或工具补证据；证据过期时处理版本与保鲜；推理链错误时给明确的检查器；工具结果不确定时停止声称成功。要求关键结论附可核查依据，让程序检查格式、数值和权限；对高风险领域加入人审。不要承诺“消灭幻觉”，要能报告剩余错误率和无法回答的情况。

### 11. Token 突然升高怎样定位

按一次 run 的时间线看系统提示、项目规则、检索片段、工具返回、历史消息、重复调用和重试次数。常见原因是一次搜索拉回过多文件、测试日志原样回填、压缩未触发、子 Agent 重复复制上下文或模型在工具错误上循环。分别记录输入/输出 token、轮数和工具结果体积；缩小片段、折叠重复日志、缓存稳定前缀并修复死循环。优化后还要看任务完成率，不能靠截断关键证据换一个好看的成本数。

### 12. 怎样设计并评估 Agent Skill

Skill 应有明确触发条件、适用范围、步骤、所需工具、失败出口和可复用资产。先用真实任务验证是否值得抽象，再给模型只展示名称与简介，命中时加载完整说明；脚本仍受工具权限约束。评估时看触发准确率、误触发率、完成率、调用成本、用户改动量和失败恢复。一次成功演示不足以上线；要测相近但不适用的负样本，以及 Skill 说明过期时的行为。

## 项目追问与后端基础：第 13～19 题

### 13～14. 项目来源、个人贡献和最难的问题

项目基于开源方案不减分，关键是说清复用部分与自己的改造：你改了哪个工具、状态节点或评测流程，为什么改，怎样测。挑一件难题讲症状、候选原因、定位证据、修复和结果。原帖没有披露候选人的项目细节或现场答案，因此这里不能替他编项目数据。若你也没有量化线上指标，可给出离线样本规模、测试通过条件和限制，不要凭空报提升百分比。

### 15. Java 线程池参数与提交路径

`ThreadPoolExecutor` 的关键项是 `corePoolSize`、`maximumPoolSize`、`keepAliveTime`、`TimeUnit`、`BlockingQueue`、`ThreadFactory` 和拒绝策略。提交任务时，运行线程少于核心数则先建核心线程；否则尝试入队；队列放不下且线程数未达最大值时建非核心线程；再放不下就执行拒绝策略。无界队列可能让最大线程数几乎派不上用场，任务堆积还会占内存。回答时把任务是 CPU 密集还是 I/O 密集、队列容量和拒绝后的业务行为一起说明。

### 16. 如果重新设计线程池

先确定负载、优先级、最大排队时间与取消语义。线程池需要有界队列、背压/拒绝、任务异常隔离、超时、可观测指标和优雅关闭；多租户任务还应避免一个租户占满全部 worker。不要只讲“动态调节线程数”，因为扩线程不能解决下游数据库或模型服务容量不足。给出队列长度、活跃线程、等待时长、拒绝率等观察量，才能判断是否需要扩容。

### 17. JVM 如何加载 Class

通常按加载、链接（验证、准备、解析）、初始化来解释。加载取得字节码并创建类元数据；验证保证格式和约束；准备为静态字段分配并设默认值；解析把符号引用转为直接引用；初始化执行类初始化逻辑。双亲委派是常见类加载器组织方式，可减少核心类被任意替换，但自定义加载器、模块和动态生成类也有特殊路径。不要把“加载了 Class 文件”直接等同于类已初始化。

### 18～19. MySQL 三种日志与两阶段提交

Undo log 保存回滚和 MVCC 所需的旧版本信息；redo log 是 InnoDB 对页修改的物理恢复依据；binlog 位于 MySQL Server 层，记录逻辑变更，常用于复制和增量恢复。三者的写入时机、粒度和用途不同。为了避免“redo 已提交但 binlog 未写”或反过来的不一致，InnoDB 与 binlog 通过 prepare/commit 两阶段配合；恢复时根据 redo 的状态和 binlog 是否完整判断事务。面试中先画出崩溃点，再解释各阶段如何恢复，比只背“三个日志的定义”更有说服力。

## 算法与收尾：第 20～21 题

### 20. 合并两个已排序数组

题目没有交代数组是否预留原地空间，先向面试官确认。若第一数组末尾有足够空位，可从后往前比较两个数组末尾，把较大值放到最终尾部，避免前移覆盖；时间复杂度 `O(m+n)`、额外空间 `O(1)`。若必须创建新数组，用双指针从头合并，时间仍为 `O(m+n)`、额外空间 `O(m+n)`。还要测一个数组为空、重复值和负数。代码写完先口述指针不变量，再用小例子检查边界。

### 21. 反问环节

可以问岗位实际负责的 Agent 场景、最重视的质量指标、工具权限如何治理、当前主要工程难点，以及新同学交付的第一类任务。问题与前面的讨论相连即可；原帖只写“反问环节”，没有提供具体提问内容，不能把这些建议写成候选人实际问过的话。

## 面试会怎么问

这场的难点是技术层次切换。回答 Agent 问题时坚持“目标—运行时动作—验证—失败出口”；回答 Java/MySQL 时切换到机制、边界和崩溃点；项目题只说亲手做过的部分。可用三分钟复盘一道故障题：工具超时后先判断是否只读、外部状态是否未知，再决定重试、对账或人工接手。
